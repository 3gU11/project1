# 交付信息购货单位/地址自动识别（2026-11-14）

## 背景

售后小程序「交付验收 → 交付信息上传」只上传东莞回传的订货合同（PDF/照片），
文件进入 V8「交付信息待处理」队列后，由 V8 操作人员打开合同预览，
在「处理交付信息」弹窗里手工填写购货单位、购货单位地址、合同机台号并勾选机台。

合同「购货方详细资料」栏位本身就含**购货单位名称/个人姓名**和**地址**，
2026-11-11 的机台号识别已经会把附件转成文本（PDF 文本层或本机 OCR），
因此可在同一次识别里把购货单位/地址也提取出来，直接预填到处理弹窗的两个输入框，
操作人员只需对照附件核对。

## 识别口径

- 名称取「购货单位名称/个人姓名」栏位之后、到「地址」栏位之前的值；
  地址取「地址」栏位之后、到「联系人/联系电话/其他特殊要求/备注」之前的值。
- 只认「购货方详细资料」里的栏位，不会把合同抬头的「需方」（经销商）或
  签署栏的「单位地址」误当成购货单位/地址。
- PDF 文本层：去掉空白后直接按栏位取值（PDF 常把名称/地址拆成多个文本块）。
- 图片/扫描件 OCR：用 OCR 文本块的坐标按视觉行重排后再取值，
  修复表格多列行序错乱（例如地址尾部「37米左右」被 OCR 排到「联系电话」之后）。
- OCR 把「有限公司」的「司」漏在单元格第二行时，若识别结果以「有限公」结尾，
  补全为「有限公司」，并在 `warnings` 里提示操作人员核对；
  个人姓名不做任何补全。
- 识别结果只填空值，不覆盖上传/操作人员已填的内容；`processed` 记录只返回结果不回填；
  附件缺失、OCR 未启动、PDF 损坏等一律只记 `warnings`，不影响上传/处理业务。

## 后端改动

- `crud/delivery_info_recognition.py`
  - 新增 `extract_buyer_info(text, items=None)`：提取购货单位名称/个人姓名与地址；
  - 新增 `build_ocr_text_rows(items)`：把 OCR 文本块按视觉行重排；
  - `recognize_delivery_info_file()` 返回值新增 `buyer_name`、`buyer_address`；
  - `recognize_delivery_info_upload()` 回填 `buyer_name`/`buyer_address`/`machine_nos`
    （只填空值，`processed` 不回填）。
- `api/routes/customer_contracts.py`
  - 上传入口：机台号、购货单位、地址任一缺失时，保存后自动识别并回填；
  - 响应 `buyerName`/`buyerAddress` 返回最终值（提交值优先，其次识别值），
    `recognition` 内含完整识别结果。
- `api/routes/delivery_info_uploads.py`
  - 重识别接口 `POST /api/v1/inventory/delivery-info-uploads/{upload_id}/recognize`
    返回新增 `buyer_name`/`buyerName`、`buyer_address`/`buyerAddress`
    （识别值优先，没有则回退到库里已存值）。
- `frontend/src/views/CustomerFinishedGoods.vue`
  - 处理弹窗工具栏新增「重新识别附件」：调用重识别接口，把识别出的
    购货单位/地址填入两个输入框（机台号输入框为空时一并填入），并提示核对；
  - 待处理列表提示文案更新为「系统会尝试识别合同里的购货单位/地址/机台号」。

## 接口契约（新增字段）

`POST /api/v1/inventory/delivery-info-uploads/{upload_id}/recognize`：

```json
{
  "data": {
    "uploadId": "16",
    "fileName": "交付信息_1794475679239.jpg",
    "status": "pending",
    "buyer_name": "东莞市锦宏精密五金制造有限公司",
    "buyerName": "东莞市锦宏精密五金制造有限公司",
    "buyer_address": "东莞市大塘路与西三横路交叉口正东方向37米左右",
    "buyerAddress": "东莞市大塘路与西三横路交叉口正东方向37米左右",
    "machine_nos": ["96-08-306"],
    "machineNos": "96-08-306",
    "raw_numbers": [],
    "machines": [],
    "method": "ocr",
    "warnings": [
      "购货单位名称疑似截断（东莞市锦宏精密五金制造有限公），已补全为「东莞市锦宏精密五金制造有限公司」，请对照附件核对"
    ],
    "persisted": true
  }
}
```

上传入口 `POST /api/v8/delivery-info-uploads` 的 `buyerName`/`buyerAddress`
同样返回最终值；`recognition` 中新增 `buyer_name`/`buyer_address`。

## 实测（待处理队列里的真实样例）

- `data/delivery-info-pending/5ba3ddce8d9a4b9ea180142058cc962c/锦宏下单表(1).pdf`：`method=pdf-text`，
  `buyer_name=东莞市锦宏精密五金制造有限公司`，
  `buyer_address=东莞市大塘路与西三横路交叉口正东方向37米左右`，`warnings=[]`。
- `交付信息_1794475679239.jpg`（手机截图）：`method=ocr`，识别出同样的购货单位/地址；

- 机台号识别不受影响：仍为 `96-08-306`。

## 遗留风险

- 截图/拍照 OCR 对画质敏感，名称/地址可能漏字；只有「有限公 → 有限公司」
  这种明确后缀会补全，其余以附件预览为准。
- 地址若横跨多行且与其它栏位 OCR 交错严重，可能只识别到前半段，操作人员需核对。
- 依赖本机 OCR 服务（`http://127.0.0.1:8010/ocr`）；未启动时只返回 warning，
  不阻断上传与处理。
