## 一、结论先行

| 问题 | 结论 |
|---|---|
| 远程最新提交是什么 | `d87fa5cbe` 配货稳定性 + 全栈集成修复（10-31） |
| push 会改云端桥吗 | **不会**。10 个云端桥文件里 9 个零差异，只有 `api/main.py` 有新增（多了个可关闭的开关，默认行为不变） |

| 主机会不会被影响 | **不会**。`git push` 只改远程仓库，主机不执行 `pull` 就完全不变 |

### `api/main.py` 的 77 行新增里，和云端有关的只有 3 处

1. **`CLOUD_SYNC_ENABLED` 开关**（新增）
   ```python
   cloud_sync_enabled = os.getenv("CLOUD_SYNC_ENABLED", "true").strip().lower() not in {"0","false","no","off"}
   ```
   默认 `true` → **不设环境变量时行为与远程完全一致**，只是多了"能关掉"的能力。

2. **库存快照心跳在演示模式下关闭**
   复用同一个开关，`CLOUD_SYNC_ENABLED=false` 时心跳只打日志、不发请求。

3. **`enqueue_wechat_batch_summary_sync("scheduled_snapshot")`**
   定时把订货读模型入队，属于原有链路的调用点补齐。

**结论**：云端桥的**数据边界、签名校验、拉取/回写逻辑一行没动**。push 之后，远程的云端桥代码与现在主机上跑的**语义等价**，只是多了个可关闭的总开关。

## 五、部署到服务器的步骤（Windows 主机，不碰现有实例）

### 0. 前置条件

- MySQL 8（字符集 `utf8mb4`）
- Python 3.11+（本机验证用 `D:\python\python.exe`，3.11.9）
- Node 20+（**只用于构建前端**，构建完可卸载）
- nginx（可选，用于 HTTPS 与移动端托管）
- 与公司主机**不同的端口**（默认 3000/5174/8000/3001/8010 与主机一致，同机部署要改）

### 1. 获取代码

```bash
git clone https://github.com/3gU11/project1.git v8-server
cd v8-server
git checkout main
```

> push 之后 `main` 才包含本次 70 个提交；在此之前只能从当前开发机拷贝工作区。

### 2. 数据库

两种选择：

| 方式 | 适用 | 操作 |
|---|---|---|
| **空库**（推荐首次） | 只验证功能、不碰生产数据 | 建库后直接启动，程序自动建表 + 写种子账号 |
| **生产副本** | 需要真实数据看效果 | 主机上 `mysqldump --single-transaction` → 服务器 `mysql < dump.sql` |

```sql
CREATE DATABASE v8 DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;
CREATE USER 'v8'@'%' IDENTIFIED BY '<强密码>';
GRANT ALL ON v8.* TO 'v8'@'%';
```

### 3. 配置 `.env`

复制 `.env.example` 后逐项填，**不要直接拷贝开发机的 `.env`**：

```ini
# 数据库（Python 与 Go 两套都要配，指向同一实例）
MYSQL_HOST=127.0.0.1
MYSQL_PORT=3306
MYSQL_USER=v8
MYSQL_PASSWORD=<强密码>
MYSQL_DB=v8
DB_DSN=v8:<强密码>@tcp(127.0.0.1:3306)/v8?charset=utf8mb4&parseTime=true

# 安全（必须）
V8_JWT_SECRET=<至少 32 位随机串>      # 不配会启动失败
GO_INTERNAL_TOKEN=<随机串>            # 不配则 /internal/* 任何人可调

# 功能开关
V8_UPLOADS_ENABLED=true               # 默认 false，上传接口会 503
OCR_ENABLED=false                     # 不用识别就保持 false

# 云端同步 —— 部署到服务器时务必关闭，否则与主机重复拉单
CLOUD_SYNC_ENABLED=false
V8_SYNC_ENABLED=false
```

### 4. 安装依赖

```powershell
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt
```

### 5. 构建前端（两个都要）

```powershell
cd frontend;        npm ci; npm run build     # 产物 frontend/dist，由 FastAPI 托管
cd ..\frontend-mobile; npm ci; npm run build  # 产物需 nginx 单独托管
```

> 仓库里的 `frontend/dist` 是旧产物（128 个文件被跟踪），**必须重新构建**。

### 6. Go 服务

**不需要编译**：直接复制现有 `server/smart-scheduling-server-go.exe`（21 MB，11-02 编译）。
如果服务器架构相同（Windows x64），可直接运行；生产机不要现场 `go build`（缓存目录巨大）。

### 7. 启动（4 个进程）

```powershell
# FastAPI
.venv\Scripts\python.exe -m uvicorn api.main:app --host 127.0.0.1 --port 8000

# Go 沙箱
server\smart-scheduling-server-go.exe

# OCR（可选）
.venv\Scripts\python.exe server\ocr_service.py

# 前端：nginx 指向 frontend/dist，或临时用 python -m http.server
```

首次启动会执行建表与种子数据，观察日志确认 `workflow tables` 初始化成功。

### 8. 验证

```bash
curl http://127.0.0.1:8000/health                    # 200
curl http://127.0.0.1:3000/                          # 200
```

登录后按顺序走一遍：登录 → 合同 → 下单 → 配货 → 发货 → 退回审批 → 流程模型（应能看到 14 个模型）。

## 六、怎样保证不破坏现有系统

### 6.1 边界

| 动作 | 对主机的影响 |
|---|---|
| `git push` | **零影响**。只写远程仓库，主机不 `pull` 就不会变 |
| 服务器部署新实例 | **零影响**，前提是：独立数据库 + `CLOUD_SYNC_ENABLED=false` |
| 服务器连生产库 | **有影响**。两个实例同时读写会互相覆盖缓存与状态，禁止 |
| 主机 `git pull` + 重启 | **有影响**。会一次性拿到 70 个提交，需按 6.2 流程做 |

### 6.2 如果之后要在主机上升级

```powershell
# 1. 备份（必做）
mysqldump --single-transaction -u root -p v8 > v8_backup_20261102.sql
Copy-Item -Recurse F:\work\V8\project1 F:\work\V8\project1_backup_20261102

# 2. 停服务
.\stop_fullstack.ps1 -WebPort 3000

# 3. 更新代码
git fetch origin && git pull --ff-only

# 4. 补依赖 + 重建前端
.venv\Scripts\pip install -r requirements.txt
cd frontend; npm ci; npm run build; cd ..

# 5. 启动（启动时自动补建 workflow_* 表与 shipping_time/row_version 列）
.\run_fullstack.ps1 -PythonExe D:\python\python.exe

# 6. 验证后观察 24 小时；异常则回滚
git reset --hard <旧提交>; .\run_fullstack.ps1 ...
# 数据库如需回滚：mysql < v8_backup_20261102.sql
```

**回滚点**：代码可 `git reset`，数据必须靠 dump。由于本次 DDL 只增不删，代码回滚后旧版本仍能读新库（多余的表和列会被忽略），所以**回滚风险很低**。

## 七、部署前检查表

- [ ] 服务器端口与主机不冲突（同机部署时改 `ApiPort`/`WebPort`）
- [ ] `.env` 里 `V8_JWT_SECRET` 已配（≥32 位），否则起不来

- [ ] Go 用编译好的 exe，不在生产机编译
- [ ] 数据库已备份（用生产副本时）
- [ ] 防火墙只放行实际需要的端口
