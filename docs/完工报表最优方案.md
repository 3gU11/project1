# 完工报表最优方案设计

## 🎯 核心需求分析

### 用户需求
1. **统计目标**：所选时间段内，总共产出了多少台机器
2. **用途**：产量统计和对账
3. **关键词**："产出"、"对账"

### 业务本质

**"产出"的本质含义**：
- 从生产角度：机器生产完成
- 从库存角度：机器进入可用状态
- 从财务角度：机器可以计入资产/成本

**对账的需求**：
- 数据必须完整（不能遗漏）
- 数据必须准确（不能重复）
- 数据必须可追溯（有明确时间点）

---

## 💡 最优方案：基于入库历史

### 核心思路

**"产出" = "入库"**

理由：
1. ✅ **业务完整性**：只有入库的机器才真正进入库存系统，才能被使用
2. ✅ **数据完整性**：入库历史记录了所有入库方式（手动+自动）
3. ✅ **时间准确性**：入库时间是明确的时间点，不会被反复更新
4. ✅ **财务对账**：入库时间通常是财务入账的依据
5. ✅ **不可变性**：入库历史是不可变的事件记录，数据可靠

### 与其他方案的对比

| 方案 | 数据来源 | 时间点 | 完整性 | 准确性 | 适合对账 |
|------|---------|--------|--------|--------|---------|
| **方案A：沙盘完工** | production_history_ledger | completed_at | ❌ 缺少直接导入 | ⚠️ 需手动点击 | ❌ 不完整 |
| **方案B：看板逻辑** | finished_goods_data.状态 | 更新时间 | ✅ 完整 | ⚠️ 状态多次变更 | ⚠️ 时间不准 |
| **方案C：入库历史** | inbound_history | inbound_time | ✅ 完整 | ✅ 准确 | ✅ 最适合 |

## 📊 方案C：基于入库历史的完工报表

### 核心逻辑

```sql
SELECT * FROM inbound_history
WHERE inbound_time BETWEEN :start_date AND :end_date
  AND COALESCE(status_after, '') <> '待入库'
  AND COALESCE(status_after, '') <> ''
```

### 完工定义

**入库 = 完工**

- 手动入库：仓库扫码入库 → 完工
- 自动入库：配货时自动入库 → 完工
- 不论哪种方式，只要入库就算产出

### 数据结构

**明细报表**：
```sql
SELECT
    DATE_FORMAT(ih.inbound_time, '%Y-%m-%d') AS `入库日期`,
    ih.serial_no AS `流水号`,
    ih.batch_no AS `批次号`,
    ih.model AS `机型`,
    ih.status_after AS `入库后状态`,
    ih.customer AS `客户`,
    ih.dealer AS `代理商`,
    ih.order_no AS `订单号`,
    ih.contract_no AS `合同号`,
    ih.slot_code AS `库位`,
    ih.operator AS `操作员`,
    ih.source AS `入库方式`,
    DATE_FORMAT(ih.inbound_time, '%Y-%m-%d %H:%i:%s') AS `入库时间`
FROM inbound_history ih
WHERE ih.inbound_time BETWEEN :start_date AND :end_date
  AND COALESCE(ih.status_after, '') <> '待入库'
  AND COALESCE(ih.status_after, '') <> ''
  AND (:model_type = '' OR ih.model = :model_type)
  AND (:customer = '' OR ih.customer = :customer)
  AND (:contract_no = '' OR ih.contract_no = :contract_no)
ORDER BY ih.inbound_time DESC
```

**汇总报表**：
```sql
SELECT
    DATE_FORMAT(ih.inbound_time, '%Y-%m-%d') AS `日期`,
    ih.batch_no AS `批次号`,
    ih.model AS `机型`,
    COUNT(*) AS `产出数量`,
    ih.customer AS `客户`,
    ih.dealer AS `代理商`,
    ih.contract_no AS `合同号`,
    -- 按入库方式分类统计
    SUM(CASE WHEN ih.source = '机台入库' THEN 1 ELSE 0 END) AS `手动入库`,
    SUM(CASE WHEN ih.source = '直接配货-自动入库' THEN 1 ELSE 0 END) AS `直接配货入库`,
    SUM(CASE WHEN ih.source = '配货自动入库' THEN 1 ELSE 0 END) AS `配货入库`,
    -- 按入库后状态分类统计
    SUM(CASE WHEN ih.status_after LIKE '库存中%' THEN 1 ELSE 0 END) AS `入库到库存`,
    SUM(CASE WHEN ih.status_after = '待发货' THEN 1 ELSE 0 END) AS `入库到待发货`
FROM inbound_history ih
WHERE ih.inbound_time BETWEEN :start_date AND :end_date
  AND COALESCE(ih.status_after, '') <> '待入库'
  AND COALESCE(ih.status_after, '') <> ''
  AND (:model_type = '' OR ih.model = :model_type)
  AND (:customer = '' OR ih.customer = :customer)
  AND (:contract_no = '' OR ih.contract_no = :contract_no)
GROUP BY DATE_FORMAT(ih.inbound_time, '%Y-%m-%d'), ih.batch_no, ih.model, ih.customer, ih.dealer, ih.contract_no
ORDER BY DATE_FORMAT(ih.inbound_time, '%Y-%m-%d') DESC
```

## ✨ 方案优势

### 1. 数据完整性 ✅

**包含所有入库方式**：
- 手动入库（仓库扫码）
- 直接配货自动入库（订单管理）
- 配货自动入库（生产计划）

**不遗漏任何机台**：
- 沙盘系统生产的机台 ✅
- 直接导入的机台 ✅
- 历史数据 ✅

### 2. 时间准确性 ✅

**入库时间是明确的时间点**：
- 不会被反复更新（不像 `finished_goods_data.更新时间`）
- 有明确的业务含义（机器进入库存的时刻）
- 适合财务对账

### 3. 数据可追溯性 ✅

**每条记录包含完整信息**：
- 入库时间、入库方式、操作员
- 入库前状态、入库后状态
- 客户、代理商、订单号、合同号
- 库位、批次号、机型

### 4. 业务语义清晰 ✅

**"产出" = "入库"**：
- 符合库存管理的业务逻辑
- 符合财务对账的需求
- 易于理解和沟通

### 5. 数据不可变 ✅

**入库历史是事件记录**：
- 一旦记录，不会修改
- 数据可靠，适合审计
- 避免数据被覆盖或丢失

## 🎯 与其他报表的关系

### 报表体系

```
┌─────────────────────────────────────────────────────────┐
│                    报表体系                              │
└─────────────────────────────────────────────────────────┘

1. 【完工报表】（新方案）
   - 数据来源：inbound_history
   - 统计维度：入库时间
   - 业务含义：产出并入库的机台
   - 用途：产量统计、财务对账

2. 【入库报表】（已有）
   - 数据来源：inbound_history
   - 统计维度：入库时间
   - 业务含义：入库操作记录
   - 用途：入库追踪、操作审计

3. 【生产完工报表】（可选，保留旧逻辑）
   - 数据来源：production_history_ledger
   - 统计维度：完工时间
   - 业务含义：沙盘系统生产完工
   - 用途：生产效率分析、产线绩效
```

### 区别说明

**完工报表 vs 入库报表**：
- **完工报表**：强调"产出数量"，用于对账
- **入库报表**：强调"入库操作"，用于追踪

**实际上**：
- 数据来源相同（`inbound_history`）
- 查询逻辑相同
- 可以合并为一个报表，提供不同的展示维度

## 🔧 实现建议

### 方案1：复用入库报表（推荐）

**优点**：
- 不需要新增代码
- 数据逻辑一致
- 维护成本低

**实现**：
- 将"入库报表"改名为"产出报表"或"完工报表"
- 或者在前端提供两个入口，指向同一个API

### 方案2：新增完工报表端点

**优点**：
- 语义更清晰
- 可以定制化展示
- 不影响现有入库报表

**实现**：
- 创建新的API端点 `/api/reports/production-output`
- 复用 `get_inbound_report_data()` 函数
- 或者创建新函数，添加更多统计维度
