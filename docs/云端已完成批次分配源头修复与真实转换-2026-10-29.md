# 云端已完成批次分配源头修复 + 真实业务转换（2026-10-29）

## 1. 问题

云端「大区经理批次分配」候选会把**已完成批次**（如 `08-04`、`09-08`）当成可分配批次，V8 转合同后无法做批次插入（批次不在产线），只能兜底为人工配货。

## 2. 根因

云端候选接口 `InventoryStore.findAllocatableBatches()` 读 V8 快照 `wechat_batch_summary`，加高行取
`original_batch_no` 作为候选批次号：

- 工厂快照把「库存中”的加高机也带了原批次号（`08-04`、`09-08` 等历史生产批次）；
- 这些原批次在 V8 本地 `batches` 表里已是 `Completed`，不在产线，无法插入合同；
- 云端并不持有 V8 批次状态，只能按快照字段展示，于是候选里出现已完成批次。

因此问题出在**快照口径**，不在云端候选 SQL 本身。

## 3. 修复

### 3.1 V8 快照口径（`crud/cloud_dealer_order_sync.py`）

- 库存中（`状态 LIKE '库存中%'`）的加高机不再携带原批次号：`original_batch_no=''`，并按「机型 + 是否加高」合并为一行；
- 加高在制（`待入库` 且有预计入库时间）仍保留原批次号，用于在制批次分配；
- 停用历史存储过程 `refresh_wechat_batch_summary_all()`（其分组仍会带出已完成批次号），统一走 Python SQL 重建；
- 同步更新 `scripts/wechat_batch_summary.sql` 中的过程口径，避免以后重装时回退。

效果：快照中加高现货变为「批次=库存中、无原批次号」；云端候选自然展示为「库存中」现货候选，不再出现已完成批次。
