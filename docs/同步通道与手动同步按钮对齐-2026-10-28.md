# 同步通道与手动同步按钮对齐（2026-10-28）

## 1. 背景

云端「同步监控 → V8 桥接上传」已按 4 条同步通道展示健康度：

| 通道 | 方向 | 设定周期 |
|---|---|---|
| 工厂库存快照 | V8 → 云端 | 5 分钟（库存变化即时触发） |
| V8 拉取订单 | 云端 → V8（拉取） | 1 分钟 |
| 机台快照同步 | V8 → 云端 | 24 小时 |
| 订单状态回调 | V8 → 云端 | 事件驱动 |

本地「经销商订单审核」页顶部的手动按钮仍是旧抽象：`同步云端`（实际是拉取，方向写反）、
`同步库存到云端`（返回契约错误，前端恒显示 0 行）、`同步完成状态`（只扫 `completed`，
本地 0 条，历史点击全部空转）。同时「机台快照同步」通道既没有自动调度、也没有手动入口，
云端回执停在 2026-10-23 19:01:38，超期 3.8 天。

## 2. 本次改动（P0：先修断链）

- [api/main.py](../api/main.py) 启动钩子恢复 v8_sync 接线：启动时 `run_startup_sync()`
  补当天机台快照，随后 `run_sync_loop()` 周期检查；shutdown 时取消任务。
  之前的 commit `41ce47e6` 只加了 `v8_sync/scheduler.py`，`api/main.py` 未接线。
- [tools/repair_sync_daily.bat](../tools/repair_sync_daily.bat)、
  [tools/repair_sync_send_pending.bat](../tools/repair_sync_send_pending.bat) 由已删除的
  `-m repair_sync` 改为 `-m v8_sync`（包重命名后脚本未同步）。
- 机台快照上传路径不变：`v8_sync.scheduler.run_daily` → `cloud_sync_outbox`（`repair_snapshot_sync`）
  → `POST /api/v8-sync/machines`；每个业务日期生成新 event_id，即使内容不变也会每天上传一次。

## 3. 本次改动（P1：按钮通道化）

- 新增 [crud/sync_channels.py](../crud/sync_channels.py)：`sync_channel_state` 表记录每条通道
  最近成功/失败/触发方式；状态判定与云端同口径（grace = max(60, min(interval/5, 1800))）。
- 自动通道写入状态：库存心跳、拉单 worker、outbox 事件（快照/机台/订单状态）成功后统一记录；
  失败记录 `last_error`。
- 新增接口：
  - `GET /api/v1/dealer-orders/sync-channels`：4 条通道的本地状态；
  - `POST /api/v1/dealer-orders/sync-machine-snapshot`：立即生成并上传一次机台快照。
- 手动按钮调整：
  - `同步云端` → `立即拉取订单`；
  - `同步库存到云端` → `推送库存快照`，并改为同步执行、返回真实 `local_rows/pushed_rows`；
  - 删除 `同步完成状态`（等价自动事件 `dealer_order_completed` 已存在，该按钮长期空转）；
  - 新增 `机台快照同步`、`同步通道` 两个入口；`同步通道` 弹窗展示设定周期/最近成功/
    预计下次/偏差/状态，并可按通道立即同步。
- 前端 `DealerOrderReview.vue` 增加通道弹窗与 30 秒自动刷新；构建产物仍走 `frontend/dist`（已 gitignore）。

## 5. 遗留

1. 云端监控的「订单状态回调」通道仍只读 `dealer_order_status_callbacks`；桥接已改为转发 Spring
   写 `integration_sync_event.status_update`，因此该行长期显示「暂无事件」。需要在云端售后仓库
   修正取数口径（不在本次改动范围）。
2. 手动触发与自动通道在云端仍不可区分；本地已记录 `last_trigger=manual/auto`，云端是否透出
   需后续联动。
3. 机台快照若连续多日无内容变化，仍依赖每日新 business_date 的 event_id 上传；建议后续把
   云端 machine interval 与本地上传节奏一同纳入配置核对。
