# 预测沙盒现状交互审计

目标：让排产员能够区分需求、预测方案、冻结计划和产线执行，并在提交前理解影响。

## 现状证据

- `PredictionSandbox.vue` 在同一页面提供全量重算、按选中列重算、批次审核、撤销审核、拖拽、卡片强改、急单和特殊卡操作。
- 预测批次和已确认批次都进入同一个 `filteredBatches` 画布。
- `productionLines.js` 只允许已确认批次进入空闲产线，产线选择仍由人工完成。
- `predictor.js` 负责交期排序、机型族归并、固定容量分批、比例补位和等待队列。

## 核心问题

1. 状态边界不够显著：`Predicted`、`Confirmed`、`In_Production` 对业务用户不是同一个决策阶段。
2. 操作语义混合：拖拽既可能是试排，也可能直接改变数据库中的批次结构。
3. 结果缺少可解释性：页面显示结果，不显示为什么延期、为什么形成该批、为什么有备货位。
4. 计划到执行断开：审核完成后需要切换到生产看板再派工。

## 验收标准

- 用户在首屏能看到当前处于“需求、模拟、待确认、待派工、生产中”的哪一阶段。
- 任一拖拽或急单操作都能看到影响摘要，并能撤销未提交变更。
- 已确认或已在产批次不会被普通全量重算覆盖。
- 每个未排合同都有明确原因。
- 从一个已确认批次可直接查看可用产线和派工限制。
- 页面能显示合同数量、备货数量、延期数量、等待队列数量和产线负荷。
