# 交付信息机台号自动识别（2026-11-11）

> 2026-11-14 起同一次识别还会提取「购货单位名称/个人姓名」和「地址」，
> 见 `docs/交付信息购货单位与地址自动识别-2026-11-14.md`。

## 背景

东莞回传的订货合同（多为 PDF/扫描件）只含机台编号（如 `9608306`）与客户信息。
V8 内部流水号形如 `96-08-306`，两边去掉非数字后一致即可判定同一台机台。
合同里还有电话（11 位）、价格（125000）、日期（202610）等干扰数字，
因此识别结果必须以「与 V8 东莞机台流水号归一化比对命中」为准，不能看到数字就当机台号。

## 后端改动

- 新增 `crud/delivery_info_recognition.py`
  - `recognize_delivery_info_file(file_path)`：识别附件文本并匹配东莞机台号；
  - `recognize_delivery_info_upload(upload_id[, file_path])`：按上传记录识别并回填；
  - `match_machine_numbers(text, machines=None)`：纯比对逻辑，测试可注入假机台；
  - 支持 `.pdf`（pypdf 文本层；无文本层 OCR 页内图片，最多 5 页/5 图）、
    `.jpg/.jpeg/.png`（本机 OCR 服务）、`.docx`（mammoth）、`.doc`（不支持，仅 warning）。
- `api/routes/customer_contracts.py` 上传入口：未传 `machine_nos` 时保存后自动识别并回填，
  响应新增 `recognition`，`machineNos` 返回最终机台号；识别失败不影响上传成功。
- `api/routes/delivery_info_uploads.py` 新增重识别接口
  `POST /api/v1/inventory/delivery-info-uploads/{upload_id}/recognize`。
- `requirements.txt` 增加 `pypdf==7.0.1`。

## 接口契约（前端使用）

### 1. 重识别（已存在待处理记录）

`POST /api/v1/inventory/delivery-info-uploads/{upload_id}/recognize`，权限 `QUERY`。

```json
{
  "data": {
    "uploadId": "88",
    "fileName": "锦宏下单表(1).pdf",
    "status": "pending",
    "machine_nos": ["96-08-306"],
    "machineNos": "96-08-306",
    "raw_numbers": [],
    "machines": [
      {
        "serial_no": "96-08-306",
        "流水号": "96-08-306",
        "model": "FR-400XS(PRO)",
        "机型": "FR-400XS(PRO)",
        "customer": "东莞市南城蛤地草塘路7号工业区（东莞市宏轩机械设备）",
        "客户": "东莞市南城蛤地草塘路7号工业区（东莞市宏轩机械设备）",
        "order_no": "SO-20261007-B71B",
        "占用订单号": "SO-20261007-B71B",
        "status": "已出库",
        "状态": "已出库",
        "location_code": "C04",
        "Location_Code": "C04",
        "matched_text": "9608306"
      }
    ],
    "method": "pdf-text",
    "warnings": [],
    "persisted": true
  }
}
```

- `machine_nos`：命中的 V8 内部流水号（前端可直接用于勾选机台）；
- `machines`：命中机台明细，中文键与「客户成品」表格列一致，英文键给脚本/新代码；
- `raw_numbers`：未命中但形如 7 位纯数字的合同机台号（人工判断用）；
- `method`：`pdf-text` / `pdf-ocr` / `ocr` / `docx` / 空；
- `warnings`：识别降级原因（OCR 未启动、PDF 损坏、`.doc` 不支持等），不影响接口 200；
- `persisted`：是否已回填 `delivery_info_uploads.machine_nos`；
  `status=processed` 的记录只返回识别结果、不回填。

### 2. 上传入口自动识别

`POST /api/v8/delivery-info-uploads`（售后小程序调用）响应新增 `recognition`：

- 调用方已传 `machine_nos`：`recognition` 为 `null`（不自动识别）；
- 未传：`recognition` 为识别结果（含 `machine_nos`/`machines`/`warnings` 等），
  `machineNos` 为最终回填值（`96-08-306`，多个用 `、` 分隔）；
- 识别异常只写 `recognition.warnings`，上传仍返回 200。

## 实测（真实样例 PDF）

`data/delivery-info-pending/0f5c5c6138f14c7d9b14e6dde50d6c4a/锦宏下单表(1).pdf`：

- `method=pdf-text`；
- `machine_nos=["96-08-306"]`，`machines[0].机型=FR-400XS(PRO)`，
  订单 `SO-20261007-B71B`，状态 `已出库`，`Location_Code=C04`；
- 排除干扰：`125000`（价格）、`202610`（日期）、`13825752665`/`13925851671`（11 位电话）；
- 未命中机台号的 7 位纯数字才进 `raw_numbers`。

## 遗留风险

- 扫描件依赖本机 OCR 服务（`http://127.0.0.1:8010/ocr`），服务未启动时只 warning；
  OCR 对图片质量敏感，可能漏识别或误识别（raw 数字可能是合同编号，如 `HX0002509`）。
- 机台号比对只覆盖「客户含东莞或库位为客户仓」的机台；不在该范围的历史机台不会命中。
- `.doc` 暂不支持；单次 OCR 总时长预算 25 秒，超时只输出已识别部分。
