# 完工报表需求与实现分析

## 🎯 核心需求

**导出所选时间段内，总共产出了多少台机器**

---

## 📊 当前实现

### 数据来源

**表**：`production_history_ledger`（生产历史台账）

**字段结构**：
```sql
CREATE TABLE production_history_ledger (
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    unit_id VARCHAR(64) NOT NULL,           -- 机台唯一ID（沙盘系统）
    production_line_id VARCHAR(64),         -- 生产产线ID
    production_line_name VARCHAR(100),      -- 生产产线名称
    batch_code VARCHAR(100),                -- 批次号
    model_type VARCHAR(100) NOT NULL,       -- 机型
    contract_no VARCHAR(100),               -- 合同号
    customer VARCHAR(255),                  -- 客户名称
    dealer_name VARCHAR(255),               -- 经销商名称
    status VARCHAR(32) NOT NULL,            -- 状态：In_Production / Completed / Cancelled
    scheduled_at DATETIME NOT NULL,         -- 排产上线时间
    completed_at DATETIME NULL,             -- 完工时间
    ...
)
```

### 查询逻辑

```sql
-- 明细查询
SELECT
    phl.unit_id AS `机台ID`,
    phl.batch_code AS `批次号`,
    phl.model_type AS `机型`,
    phl.contract_no AS `合同号`,
    phl.customer AS `客户`,
    phl.dealer_name AS `经销商`,
    phl.production_line_name AS `产线`,
    DATE_FORMAT(phl.scheduled_at, '%Y-%m-%d %H:%i') AS `排产时间`,
    DATE_FORMAT(phl.completed_at, '%Y-%m-%d %H:%i') AS `完工时间`,
    TIMESTAMPDIFF(HOUR, phl.scheduled_at, phl.completed_at) AS `生产时长(小时)`,
    COALESCE(u.serial_no, u.forecast_serial_no) AS `流水号`
FROM production_history_ledger phl
LEFT JOIN units u ON u.unit_id = phl.unit_id
WHERE phl.completed_at BETWEEN :start_date AND :end_date
  AND phl.status = 'Completed'
ORDER BY phl.completed_at DESC

-- 汇总查询
SELECT
    DATE_FORMAT(phl.completed_at, '%Y-%m-%d') AS `完工日期`,
    phl.contract_no AS `合同号`,
    phl.model_type AS `机型`,
    COUNT(*) AS `完工数量`,
    phl.customer AS `客户`,
    phl.dealer_name AS `经销商`,
    phl.production_line_name AS `产线`,
    phl.batch_code AS `批次号`,
    ROUND(AVG(TIMESTAMPDIFF(HOUR, phl.scheduled_at, phl.completed_at)), 1) AS `平均生产时长(小时)`
FROM production_history_ledger phl
WHERE phl.completed_at BETWEEN :start_date AND :end_date
  AND phl.status = 'Completed'
GROUP BY DATE_FORMAT(phl.completed_at, '%Y-%m-%d'), phl.contract_no,
         phl.model_type, phl.customer, phl.dealer_name,
         phl.production_line_name, phl.batch_code
ORDER BY DATE_FORMAT(phl.completed_at, '%Y-%m-%d') DESC
```

### 筛选条件

- `start_date` / `end_date`：完工时间范围
- `model_type`：机型筛选（可选）
- `customer`：客户筛选（可选）
- `contract_no`：合同号筛选（可选）

## ⚠️ 潜在问题分析

### 问题1：数据来源的局限性

**`production_history_ledger` 表的数据来源**：

1. **沙盘系统排产**：
   - 当机台在沙盘系统中排产时，创建记录（`status = 'In_Production'`）
   - 当机台完工时，更新记录（`status = 'Completed'`, `completed_at = 完工时间`）

2. **历史数据迁移**：
   - 系统升级时，从 `units` 表迁移生产中的机台

**可能的问题**：

❌ **不通过沙盘系统生产的机台没有记录**
- 如果机台直接导入到 `finished_goods_data`（待入库清单）
- 如果机台通过其他方式入库
- 这些机台不会出现在完工报表中

❌ **历史数据可能不完整**
- 沙盘系统上线前的机台没有完工记录
- 可能导致报表数据与实际产出不符

---

### 问题2：流水号可能为空

```sql
COALESCE(u.serial_no, u.forecast_serial_no) AS `流水号`
```

**问题**：
- 沙盘系统中的机台（`units` 表）可能还没有绑定实物流水号
- 报表中可能显示 `forecast_serial_no`（预测流水号，如 `SN-FORECAST-001`）
- 用户可能期望看到真实的流水号

**影响**：
- 报表中的流水号可能不是实际的实物流水号
- 难以与 `finished_goods_data` 中的数据对应

---

### 问题3：完工 ≠ 入库

**业务流程**：
```
排产 → 生产中 → 完工 → 入库 → 配货 → 出库
       ↑                ↑
   沙盘系统记录      入库报表记录
```

**差异**：
- **完工报表**：统计生产完工的机台（基于 `production_history_ledger`）
- **入库报表**：统计实际入库的机台（基于 `inbound_history`）

**可能的问题**：
- 完工后还未入库的机台：在完工报表中，但不在入库报表中
- 直接导入的机台：在入库报表中，但不在完工报表中

---

### 问题4：数据一致性

**场景**：如果用户想知道"某个时间段总共产出了多少台机器"

**可能的理解**：
1. **理解A**：生产线完工了多少台（基于 `production_history_ledger`）
2. **理解B**：实际入库了多少台（基于 `inbound_history`）
3. **理解C**：库存中新增了多少台（基于 `finished_goods_data` 的创建时间）

**当前实现**：理解A（生产线完工）

**问题**：
- 如果用户期望的是理解B或C，当前报表可能不满足需求
- 不同数据源可能导致数量不一致

## 💡 解决方案建议

### 方案1：保持当前实现（推荐用于沙盘系统生产）

**适用场景**：
- 所有机台都通过沙盘系统排产和生产
- 需要追踪生产线效率、生产时长等信息

**优点**：
- ✅ 包含生产线、排产时间、生产时长等详细信息
- ✅ 可以分析生产效率

**缺点**：
- ❌ 不包含直接导入的机台
- ❌ 历史数据可能不完整

**改进建议**：
- 在报表说明中明确：此报表统计的是"通过沙盘系统生产完工"的机台
- 提供数据完整性检查工具

---

### 方案2：基于入库历史（推荐用于实际产出统计）

**数据来源**：`inbound_history` 表

**查询逻辑**：
```sql
SELECT
    DATE_FORMAT(ih.inbound_time, '%Y-%m-%d') AS `入库日期`,
    ih.batch_no AS `批次号`,
    ih.model AS `机型`,
    COUNT(*) AS `数量`,
    ih.customer AS `客户`,
    ih.dealer AS `代理商`
FROM inbound_history ih
WHERE ih.inbound_time BETWEEN :start_date AND :end_date
  AND COALESCE(ih.status_after, '') <> '待入库'
  AND COALESCE(ih.status_after, '') <> ''
GROUP BY DATE_FORMAT(ih.inbound_time, '%Y-%m-%d'), ih.batch_no, ih.model, ih.customer, ih.dealer
ORDER BY DATE_FORMAT(ih.inbound_time, '%Y-%m-%d') DESC
```

**优点**：
- ✅ 包含所有入库的机台（手动入库 + 自动入库）
- ✅ 数据完整性更好
- ✅ 与实际库存数据一致

**缺点**：
- ❌ 没有生产线、生产时长等信息
- ❌ 入库时间 ≠ 完工时间（可能有延迟）

**建议**：
- 将当前的"完工报表"改名为"生产完工报表"
- 新增"实际产出报表"（基于入库历史）

---

### 方案3：基于库存创建时间

**数据来源**：`finished_goods_data` 表

**查询逻辑**：
```sql
SELECT
    DATE_FORMAT(fg.更新时间, '%Y-%m-%d') AS `日期`,
    fg.批次号 AS `批次号`,
    fg.机型 AS `机型`,
    COUNT(*) AS `数量`,
    fg.客户 AS `客户`,
    fg.代理商 AS `代理商`
FROM finished_goods_data fg
WHERE fg.更新时间 BETWEEN :start_date AND :end_date
  AND fg.状态 <> '已出库'
GROUP BY DATE_FORMAT(fg.更新时间, '%Y-%m-%d'), fg.批次号, fg.机型, fg.客户, fg.代理商
ORDER BY DATE_FORMAT(fg.更新时间, '%Y-%m-%d') DESC
```

**优点**：
- ✅ 包含所有库存中的机台
- ✅ 简单直接

**缺点**：
- ❌ `更新时间` 可能不准确（可能被多次更新）
- ❌ 没有明确的"产出时间"概念

**不推荐**：数据准确性较差

## 🎯 推荐方案

### 方案：提供两种报表

#### 1. **生产完工报表**（当前实现）

**用途**：追踪沙盘系统中的生产完工情况

**数据来源**：`production_history_ledger`

**包含信息**：
- 完工时间、排产时间、生产时长
- 生产线、批次号、机型
- 客户、经销商、合同号
- 流水号（可能为预测流水号）

**适用场景**：
- 生产效率分析
- 产线绩效统计
- 生产计划执行情况

---

#### 2. **实际产出报表**（新增，基于入库历史）

**用途**：统计实际产出并入库的机台数量

**数据来源**：`inbound_history`

**包含信息**：
- 入库时间、入库方式（手动/自动）
- 批次号、机型、状态
- 客户、经销商、订单号
- 流水号（实物流水号）
- 库位、操作员

**适用场景**：
- 实际产出统计
- 库存增长分析
- 与财务对账

**实现**：
- 复用入库报表的逻辑
- 或者创建新的"产出报表"端点

```

- 如需查看所有产出机台，请使用"实际产出报表"
```

### 3. 优化流水号显示

在报表中区分真实流水号和预测流水号：
```sql
CASE
    WHEN u.serial_no IS NOT NULL AND u.serial_no != '' THEN u.serial_no
    WHEN u.forecast_serial_no IS NOT NULL THEN CONCAT('[预测] ', u.forecast_serial_no)
    ELSE '未绑定'
END AS `流水号`
```
