# 经销商订单一键取消（配货阶段释放库存）实施说明

> 日期：2026-11-12
> 范围：V8 经销商订单审核（小程序订单）→ 转合同 → 销售订单 → 配货（订单配货）
> 目标：客户在配货阶段取消时，能一键停止并释放未出库配货，同步取消合同/销售订单，并把「已取消」回传小程序。

## 1. 问题现象

经销商订单审核页收到的小程序订单，经「审核通过 → 转合同 → 导入销售订单 → 订单配货」之后，
如果客户要取消，原先需要跨 3 个页面、分 4 步手工逆向：

1. 「订单配货」页勾选机台 → 撤回配货（`allocation-recall`，自动通过）；
2. 「销售订单」页删除订单（`order-delete`，需逆向审批）；
3. 「合同管理」页取消合同（`contract-cancel`，需逆向审批）；
4. 只有合同取消后，经销商订单才可能被联动取消并回传小程序。

存在的问题：

- 配货阶段的订单在审核页没有「取消」入口，业务人员只能拼手工流程；
- `order-delete` / `contract-cancel` 两个逆向审批执行器只处理销售订单/合同/机台，
  **不联动经销商订单、不写云端回传事件**，小程序端状态停在「已配货」；
- 合同取消清理只清 `units` 沙盘绑定，配货占用的 `finished_goods_data`（状态=待发货）
  仍挂着订单号，机台无法被其它订单使用，库存没有真正释放。

## 2. 解决思路

在「经销商订单审核」页增加**一键取消**入口，把「释放配货库存 + 取消合同 + 取消销售订单 +
经销商订单置已取消 + 云端回传」收敛为一次操作，并接入现有逆向流程框架：

- 新增逆向流程 `dealer-order-cancel`（取消经销商订单）：
  - 默认模型图为「发起 → 执行 → 通知入库员 → 结束」，**无审批节点 = 自动通过**；
  - 管理员可在「流程模型编辑器」给该模型加审批节点，之后取消会先提交审批，
    审批通过后才执行释放（无需改代码）；
- 取消动作先做**影响预览**，业务人员确认后执行；
- 只释放**未出库**的配货：已出库/已发货机台不允许自动取消，提示走「发货复核 → 退换货处理」。

## 3. 处理口径（与业务确认）

| 对象 | 取消后的处理 |
| --- | --- |
| 库存现货机台（`finished_goods_data.状态=待发货`，有库位） | 状态恢复为 `库存中（库位）`，清空占用订单号/客户/代理商/合同号 |
| 在产/待入库机台 | 状态改为 `待入库`，清空占用，并生成**重入库派生任务**通知入库员 |
| 已出库/已发货机台 | **不自动处理**，预览即阻止取消，提示走退换货 |
| `units` 沙盘绑定 | 清空合同/客户/经销商/销售订单/锁 |
| `factory_plan` 合同 | `状态=已取消`、`订单号=NULL`，同时清理 `production_queue` 等待行、
`rush_order_queue` 待处理、`production_history_ledger` 在产台账（表存在时） |
| `sales_orders` 销售订单 | 软删除 `status=deleted`，写入 `delete_reason` |
| `dealer_orders` 经销商订单 | 全部明细行 `status=cancelled`、`allocated_qty=0`、`factory_pending=0`、记录审核人/原因 |
| 小程序云端 | 入队 `dealer_order_cancelled`（整单，不带 `line_nos`），先作废旧 pending 回传事件 |

可取消状态：`approved` / `contracted` / `partial_allocated` / `allocated`。
`pending` 请用「驳回」；`cancelled` 幂等提示；`completed` 与「新备注待复审
（`factory_pending=1`）」阻止。

## 4. 接口与前端

- `GET /api/v1/dealer-orders/{order_no}/cancel-preview`（权限 `DEALER_ORDER_REVIEW`）
  返回：`cancellable`、`blockers`、`warnings`、`contracts`、`sales_orders`、
  `machines{total,stock,production,serials}`、`shipped_machines`、`lines`。
- `POST /api/v1/dealer-orders/{order_no}/cancel`（权限 `DEALER_ORDER_REVIEW`，body `{reason}`）
  返回：`message`、`status`、`approval_pending`、`instance_no`、`preview`、`result`。
  - 默认图自动通过：立即执行并返回释放/取消数量；
  - 模型加审批节点后：返回 `approval_pending=true`，审批通过后由流程执行器完成释放。
- 前端 `DealerOrderReview.vue`：
  - 表格行与详情抽屉新增「取消订单」按钮（仅可取消状态可用）；
  - 先预览：不可取消时弹阻塞原因（含已出库流水号与退换货指引）；
  - 可取消时弹确认框，展示合同/销售订单/待释放机台（库存现货、在产预占、流水号）、
    红色后果提示与取消原因；确认后调用取消接口并刷新列表；
  - 成功后提示「已释放 n 台机台，取消 n 个合同、n 个销售订单，已回传小程序」。

## 7. 已知限制与后续建议

1. `idempotency_key` 固定为 `dealer-order-cancel:{order_no}`：取消申请被驳回/撤回后，
   再次发起会命中同一实例并返回「当前状态未自动执行」。如需支持驳回后重新申请，
   需要在 workflows 侧作废旧实例或调整幂等键策略。
2. 执行阶段失败（如系统没有可用入库员、预览后机台被并发发货/改配）时：业务级联整体回滚，
   前端返回「取消执行失败：原因」，流程实例立即标记为「执行异常」并释放对象锁，
   可在「审批中心」重试/作废后重新发起，不会卡在「执行中」占锁。
3. 原有「合同管理 → 取消合同」「销售订单 → 删除订单」两条逆向入口仍未联动经销商订单与
   云端回传；本次只在经销商订单审核页收敛了「客户取消」场景，建议后续统一到同一级联服务，
   避免业务从旧入口操作后小程序状态不一致。
4. 重入库派生任务依赖系统存在 active 的入库员账号，否则取消会因无法创建任务而失败
   （与撤回配货的既有行为一致）。
5. 可选表（`production_queue` / `rush_order_queue` / `production_history_ledger`）
   按表/列存在与否降级清理，缺表环境不会阻断取消。
