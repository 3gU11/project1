# 订单状态回传与合同取消联动修复说明（2026-10-24）

> 适用目录：`D:\CURSORpj\V8BetaV1.1`（V8 端）与 `D:\CURSORpj\订货小程序`（订货小程序服务端）
>
> 现象：合同管理里合同已取消，但经销商订单仍显示「已转合同」，订货小程序也收不到取消状态回传。

## 1. 根因

1. V8 取消合同的三个入口（合同管理页「取消合同」、Go 标记现货回调 `internal/contract-cancel-sync`、历史数据）只清理了
   `factory_plan` / `units` / 排产队列，**没有联动 `dealer_orders`**，也没有写入 `cloud_sync_outbox` 回传事件。
2. `cloud_sync_outbox` 没有「订单取消」事件类型，`v8-status` 回写函数也不支持 `cancelled`。
3. 云端订单拉取 `fetch_cloud_dealer_orders("all")` 的去重键缺少顶层 `id` 兜底（云端接口 `order_no AS id`），
   所有订单都被折叠成 1 条，导致 V8 每轮只同步 1 个订单的状态。
4. 云端 `v8-status` 回调缺少终态保护，晚到的旧事件（如重试中的 `allocated`）会把 `cancelled` 覆盖回去。

## 2. 修复内容

### 2.1 V8 端

| 文件 | 改动 |
|---|---|
| `crud/dealer_orders.py` | 新增 `cancel_dealer_orders_for_contracts()`：合同取消时按「行引用的每个合同都存在且已取消」的保守口径把订单行置为 `cancelled`，同一事务写入回传事件；行级/整单事件区分 `line_nos`；取消前作废旧事件保证幂等。`_sync_allocation_status` 按真实聚合状态回传（`partial_allocated` 不再发成 `allocated`，`completed` 走完成事件）；附加备注复审不再硬编码 `approved`。 |
| `api/routes/planning.py` | 「取消合同」与 Go 标记现货 `contract-cancel-sync` 在同一事务内联动取消订单并入队回传；重复取消已是「已取消」的合同不再 404，而是幂等补同步。 |
| `crud/cloud_sync_outbox.py` | 新增事件类型 `dealer_order_cancelled` 及 dispatch；`dealer_order_allocated` 透传真实状态；新增 stale 丢弃：本地订单状态已高于事件目标状态时直接跳过（不再发 HTTP，事件记账为 synced）；新增 `supersede_pending_order_sync_events()` 作废同订单旧事件。 |
| `crud/cloud_dealer_order_sync.py` | 新增 `push_cloud_cancel()`（支持整单取消与 `items` 行级取消）；`push_cloud_review()` / `push_cloud_allocate()` 支持全部云端可写状态；修复云端订单拉取去重键（`order_no/orderNo/id` 兜底）。 |
| `tools/repair_dealer_orders_for_cancelled_contracts.py` | 历史数据修复脚本：默认 dry-run，`--apply` 写库并入队回传；判定与业务路径一致（每个引用合同都存在且状态为「已取消」）。 |

### 2.2 订货小程序服务端

| 文件 | 改动 |
|---|---|
| `server/factory_order_status.js`（新增） | 订单状态常量/别名/可写集合/整单状态推导/`shouldRejectTerminalOverwrite()` 纯函数。 |
| `server/dealer_api_node.js` | `v8-status` 接受 `cancelled`；行级取消；终态保护（`cancelled` 不再被非取消事件覆盖，`completed` 只接受 `completed/cancelled`）；取消时清零 `allocated_qty/approved_qty`；订单列表整单状态推导优先 `cancelled`；取消单不再占用批次。 |
| `miniprogram/pages/order-detail/index.js` | 详情页状态文案补 `cancelled: 已取消`。 |
| `miniprogram/pages/orders/index.js` | 订单筛选补「已取消」。 |
| `miniprogram/utils/order.js` | 已取消订单视为终态，不可再编辑附加备注。 |

## 3. 状态回传对照

| V8 本地状态 | outbox 事件 | 云端回写 `status` |
|---|---|---|
| 已通过 `approved` | `dealer_order_reviewed` | `approved` |
| 已转合同 `contracted` | `dealer_order_contracted` | `contracted` |
| 部分配货 `partial_allocated` | `dealer_order_allocated` | `partial_allocated` |
| 已配货 `allocated` | `dealer_order_allocated` | `allocated` |
| 已驳回 `rejected` | `dealer_order_reviewed` | `rejected` |
| 已取消 `cancelled` | `dealer_order_cancelled` | `cancelled` |
| 已完成 `completed` | `dealer_order_completed` | `completed` |

1. V8 端：重启 FastAPI（`start-fastapi-stable.ps1`），后台 `cloud sync worker` 会消费新的回传事件。
2. 订货小程序服务端：发布 `server/` 改动并重启 dealer API（无新增依赖、无数据库迁移）。
3. 小程序前端：微信开发者工具重新上传发布，才能看到详情页「已取消」文案与「已取消」筛选项。
4. 如之前有 `failed` 事件，可在 V8 经销商订单审核页点击「Retry」或调用
   `POST /api/v1/dealer-orders/cloud-sync-retry` 重放；云端终态保护会安全跳过过期事件。
