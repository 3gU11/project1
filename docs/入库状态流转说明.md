# 入库状态流转说明

## 📊 机台状态定义

系统中机台有以下几种主要状态：

| 状态 | 说明 | 是否在库 |
|------|------|---------|
| `待入库` | 机台已生产完成，等待入库 | ❌ 否 |
| `库存中（库位）` | 机台已入库，存放在指定库位 | ✅ 是 |
| `待发货` | 机台已分配给订单，等待出库发货 | ✅ 是 |
| `已出库` | 机台已发货出库 | ❌ 否 |

---

## 🔄 入库历史记录的触发条件

### 场景1：手动入库（仓库扫码入库）

**触发条件**：
- 机台当前状态：**任何非"库存中"的状态**（通常是"待入库"）
- 操作：仓库人员扫码入库到指定库位

**状态变化**：
```
任何状态 → 库存中（A01）
```

**记录内容**：
```python
status_before: "待入库"  # 或其他原状态
status_after: "库存中（A01）"
source: "机台入库"
```

**代码逻辑** (`crud/inventory.py:536-558`):
```python
current_status = str(row[1] or "").strip()
# 检查：如果已经是"库存中"，拒绝重复入库
if not is_transfer and current_status.startswith("库存中"):
    return {"ok": False, "code": "E_ALREADY_INBOUND", "message": "机台已入库"}

# 更新状态为"库存中（库位）"
status_after = f"库存中（{slot_code}）"

# 记录入库历史（调拨操作除外）
if not is_transfer:
    record_inbound_history(
        conn,
        [serial_no],
        source="机台入库",
        operator=operator,
        slot_code=slot_code,
        status_before=current_status,  # 原状态
        status_after=status_after,      # 库存中（库位）
    )
```

### 场景2：直接配货自动入库

**触发条件**：
- 机台当前状态：**必须是"待入库"**
- 操作：订单直接配货时，系统检测到"待入库"状态的机台

**状态变化**：
```
待入库 → 待发货
```

**记录内容**：
```python
status_before: "待入库"
status_after: "待发货"
source: "直接配货-自动入库"
```

**代码逻辑** (`crud/orders.py:223-273`):
```python
# 筛选出状态为"待入库"的机台
current_status_df = df[df['流水号'].isin(selected_sns)]
pending_inbound_sns = current_status_df[
    current_status_df['状态'] == '待入库'
]['流水号'].tolist()

# 构建状态映射（记录每台机器的原状态）
pending_status_map = {
    str(row.get("流水号", "")).strip(): str(row.get("状态", "") or "").strip()
    for _, row in current_status_df.iterrows()
}

# 更新所有配货机台状态为"待发货"
UPDATE finished_goods_data
SET 状态 = '待发货', 占用订单号 = :order_id, ...
WHERE 流水号 IN :sns AND 状态 != '已出库'

# 只记录原本是"待入库"的机台
if pending_inbound_sns:
    record_inbound_history(
        conn,
        pending_inbound_sns,           # 只记录待入库的机台
        source="直接配货-自动入库",
        status_before=pending_status_map,  # 待入库
        status_after="待发货",
    )
```

**关键点**：
- ✅ **只记录原状态为"待入库"的机台**
- ❌ 如果机台已经是"库存中"或其他状态，配货时**不会记录入库历史**
- 💡 这是因为"库存中"的机台已经有入库记录了，配货只是状态变更

### 场景3：配货自动入库（生产计划配货）

**触发条件**：
- 机台当前状态：**必须是"待入库"**
- 操作：生产计划模块进行订单配货

**状态变化**：
```
待入库 → 待发货
```

**记录内容**：
```python
status_before: "待入库"
status_after: "待发货"
source: "配货自动入库"
```

**代码逻辑** (`api/routes/planning.py:1189-1220`):
```python
# 筛选出状态为"待入库"的机台
pending_inbound_df = allocated_df[
    allocated_df["状态"].astype(str).str.strip() == "待入库"
].copy()
pending_inbound_serials = pending_inbound_df["流水号"].tolist()

# 构建状态映射
pending_status_map = {
    str(row.get("流水号", "")).strip(): str(row.get("状态", "") or "").strip()
    for _, row in pending_inbound_df.iterrows()
}

# 更新所有配货机台状态为"待发货"
UPDATE finished_goods_data
SET 状态 = '待发货', 更新时间 = :now
WHERE 流水号 IN :sns AND 状态 != '已出库'

# 只记录原本是"待入库"的机台
if pending_inbound_serials:
    record_inbound_history(
        conn,
        pending_inbound_serials,      # 只记录待入库的机台
        source="配货自动入库",
        status_before=pending_status_map,  # 待入库
        status_after="待发货",
    )
```

**关键点**：
- ✅ **只记录原状态为"待入库"的机台**
- ❌ 如果配货的机台已经是"库存中"状态，**不会记录入库历史**

## 🎯 核心规则总结

### ✅ 会记录入库历史的情况

| 场景 | 原状态 | 新状态 | source标识 |
|------|--------|--------|-----------|
| 手动入库 | 待入库 | 库存中（库位） | 机台入库 |
| 手动入库 | 其他状态 | 库存中（库位） | 机台入库 |
| 直接配货 | **待入库** | 待发货 | 直接配货-自动入库 |
| 配货 | **待入库** | 待发货 | 配货自动入库 |

### ❌ 不会记录入库历史的情况

| 场景 | 原状态 | 新状态 | 原因 |
|------|--------|--------|------|
| 库存调拨 | 库存中（A01） | 库存中（B02） | 只是库位变更，不是入库 |
| 配货 | **库存中** | 待发货 | 已有入库记录，只是状态变更 |
| 配货 | **待发货** | 待发货 | 重复配货，不是入库 |

## 💡 设计理念

### 为什么配货时只记录"待入库"状态的机台？

1. **避免重复记录**
   - "库存中"的机台已经通过"手动入库"记录过入库历史
   - 配货只是状态变更（库存中 → 待发货），不是新的入库事件

2. **准确反映入库时间**
   - "待入库"机台配货时，这是它**第一次进入库存系统**
   - 入库时间 = 配货时间，准确反映了实际入库时刻

3. **业务逻辑清晰**
   - 手动入库：物理入库，扫码放入库位
   - 配货自动入库：逻辑入库，直接分配给订单（跳过物理入库）

### 状态判断逻辑

```python
# 判断是否需要记录入库历史
if current_status == "待入库":
    # ✅ 需要记录：这是第一次入库
    record_inbound_history(...)
elif current_status.startswith("库存中"):
    # ❌ 不记录：已经有入库记录了
    pass
elif current_status == "待发货":
    # ❌ 不记录：已经配货过了
    pass
```

## 📊 入库报表过滤逻辑

报表查询时会过滤掉无效记录：

```sql
WHERE ih.inbound_time BETWEEN :start_date AND :end_date
    AND COALESCE(ih.status_after, '') <> '待入库'  -- 排除未完成入库
    AND COALESCE(ih.status_after, '') <> ''        -- 排除空状态
```

**原因**：
- `status_after = '待入库'`：表示入库操作未完成或失败
- `status_after = ''`：表示数据异常或不完整

## 🔍 常见问题

### Q1: 为什么有些机台配货时没有入库记录？
**A**: 如果机台在配货前已经是"库存中"状态，说明它已经通过手动入库记录过了。配货只是状态变更，不会重复记录。

### Q2: "待入库"机台配货后，入库时间是什么时候？
**A**: 入库时间 = 配货时间。因为这是机台第一次进入库存系统的时刻。

### Q3: 调拨操作会记录入库历史吗？
**A**: 不会。调拨（`is_transfer=True`）只是库位变更，不是新的入库事件。

### Q4: 如何区分手动入库和自动入库？
**A**: 通过 `source` 字段：
- `机台入库`：手动扫码入库
- `直接配货-自动入库`：订单直接配货时自动入库
- `配货自动入库`：生产计划配货时自动入库

## 📝 开发者注意事项

### 添加新的入库场景时

1. **明确状态判断**：确定哪些原状态需要记录入库历史
2. **避免重复记录**：检查是否已有入库记录
3. **选择合适的source**：使用清晰的标识符
4. **记录完整信息**：包括操作员、库位、时间等

### 示例代码模板

```python
# 获取当前状态
current_status = get_current_status(serial_no)

# 判断是否需要记录入库历史
if current_status == "待入库":
    # 更新状态
    update_status(serial_no, new_status)
    
    # 记录入库历史
    record_inbound_history(
        conn,
        [serial_no],
        source="你的场景名称",
        operator=operator,
        status_before=current_status,
        status_after=new_status,
    )
else:
    # 只更新状态，不记录入库历史
    update_status(serial_no, new_status)
```
