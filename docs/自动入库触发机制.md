# 自动入库触发机制说明

## 🎯 什么是自动入库？

**自动入库**是指：状态为"待入库"的机台，在特定业务操作时，**自动跳过物理入库环节**，直接变为"待发货"状态，并记录入库历史。

这是一种**逻辑入库**，不需要仓库人员扫码，系统自动完成。

---

## 🔄 自动入库的2种触发场景

### 场景1：直接配货-自动入库

#### 触发时机
当用户在**订单管理**模块进行**直接配货**操作时。

#### 操作路径
```
订单管理 → 选择订单 → 直接配货 → 选择机台 → 确认配货
```

#### 触发条件
1. 用户选择了状态为"待入库"的机台进行配货
2. 系统检测到这些机台还未入库
3. 自动将这些机台标记为"已入库"并变为"待发货"

#### 代码位置
`crud/orders.py:217-273` - `allocate_inventory()` 函数

#### 详细流程
```python
def allocate_inventory(order_id, customer, agent, selected_sns, operator=None):
    # 1. 获取当前库存数据
    df = get_data()
    
    # 2. 筛选出用户选择的机台
    current_status_df = df[df['流水号'].isin(selected_sns)]
    
    # 3. 找出状态为"待入库"的机台
    pending_inbound_sns = current_status_df[
        current_status_df['状态'] == '待入库'
    ]['流水号'].tolist()
    
    # 4. 如果有"待入库"的机台，记录日志
    if pending_inbound_sns:
        append_log("直接配货-自动入库", pending_inbound_sns, operator=operator)
    
    # 5. 更新所有选中机台的状态为"待发货"
    UPDATE finished_goods_data
    SET 状态 = '待发货',
        占用订单号 = :order_id,
        客户 = :customer,
        代理商 = :agent
    WHERE 流水号 IN :sns AND 状态 != '已出库'
    
    # 6. 记录"待入库"机台的入库历史
    if pending_inbound_sns:
        record_inbound_history(
            conn,
            pending_inbound_sns,
            source="直接配货-自动入库",
            operator=operator,
            status_before="待入库",
            status_after="待发货"
        )
```

#### 状态变化
```
待入库 → 待发货
```

#### 业务含义
- 机台生产完成后，直接分配给订单
- 跳过物理入库环节（不需要扫码入库到库位）
- 适用于：紧急订单、直发订单等场景

---

### 场景2：配货自动入库

#### 触发时机
当用户在**生产计划**模块进行**订单配货完成**操作时。

#### 操作路径
```
生产计划 → 订单配货 → 选择订单 → 配货机台 → 完成配货
```

#### 触发条件
1. 订单已经配货完成（所有需求机型都已分配）
2. 配货的机台中包含状态为"待入库"的机台
3. 用户点击"完成配货"按钮

#### 代码位置
`api/routes/planning.py:1138-1240` - `POST /api/planning/orders/{order_id}/allocate` 端点

#### 详细流程
```python
@router.post("/api/planning/orders/{order_id}/allocate")
def complete_order_allocation(order_id: str, ...):
    # 1. 验证订单存在且未完成配货
    orders_df = get_orders()
    hit = orders_df[orders_df["订单号"] == order_id]
    if hit.empty:
        raise HTTPException(404, "订单不存在")
    
    # 2. 检查配货是否完成（数量是否满足需求）
    demand_counts = _parse_order_demand_counts(hit.iloc[0])
    allocated_df = inv_df[inv_df["占用订单号"] == order_id]
    
    # 验证每个机型的配货数量
    for model, need in demand_counts.items():
        allocated = allocated_counts.get(model, 0)
        if allocated < need:
            raise HTTPException(422, f"{model} 缺少 {need - allocated} 台")
    
    # 3. 找出状态为"待入库"的机台
    pending_inbound_df = allocated_df[
        allocated_df["状态"] == "待入库"
    ].copy()
    pending_inbound_serials = pending_inbound_df["流水号"].tolist()
    
    # 4. 更新所有配货机台的状态为"待发货"
    UPDATE finished_goods_data
    SET 状态 = '待发货', 更新时间 = :now
    WHERE 流水号 IN :sns AND 状态 != '已出库'
    
    # 5. 记录"待入库"机台的入库历史
    if pending_inbound_serials:
        record_inbound_history(
            conn,
            pending_inbound_serials,
            source="配货自动入库",
            operator=current_operator,
            status_before="待入库",
            status_after="待发货"
        )
    
    # 6. 更新订单状态为"ready"（配货完成）
    orders_df.at[order_idx, "status"] = "ready"
    save_orders(orders_df)
```

#### 状态变化
```
待入库 → 待发货
```

#### 业务含义
- 生产计划已经为订单分配了机台
- 配货完成时，自动将"待入库"机台标记为已入库
- 适用于：计划性配货、批量配货等场景

## 🔍 自动入库的判断逻辑

### 核心代码模式

两种自动入库都遵循相同的判断逻辑：

```python
# 1. 获取配货的机台列表
allocated_df = inv_df[inv_df["占用订单号"] == order_id]

# 2. 筛选出状态为"待入库"的机台
pending_inbound_df = allocated_df[
    allocated_df["状态"].astype(str).str.strip() == "待入库"
].copy()

# 3. 提取流水号列表
pending_inbound_serials = pending_inbound_df["流水号"].tolist()

# 4. 构建状态映射（记录每台机器的原状态）
pending_status_map = {
    str(row.get("流水号", "")).strip(): str(row.get("状态", "") or "").strip()
    for _, row in pending_inbound_df.iterrows()
}

# 5. 更新所有配货机台状态为"待发货"
UPDATE finished_goods_data
SET 状态 = '待发货', ...
WHERE 流水号 IN :all_serials AND 状态 != '已出库'

# 6. 只记录"待入库"机台的入库历史
if pending_inbound_serials:
    record_inbound_history(
        conn,
        pending_inbound_serials,      # 只记录待入库的
        source="xxx-自动入库",
        status_before=pending_status_map,  # 待入库
        status_after="待发货"
    )
```

### 关键点

1. **只记录"待入库"状态的机台**
   - 如果配货的机台已经是"库存中"状态，不会记录入库历史
   - 因为"库存中"的机台已经通过手动入库记录过了

2. **批量处理**
   - 一次配货可能涉及多台机器
   - 系统会批量更新状态，但只记录"待入库"的机台

3. **事务保证**
   - 状态更新和入库历史记录在同一个数据库事务中
   - 要么全部成功，要么全部回滚

## 🎯 完整的入库流程对比

### 方式1：手动入库（物理入库）

```
生产完成 → 待入库 → [仓库扫码] → 库存中（库位） → [配货] → 待发货 → [出库] → 已出库
                      ↑
                   记录入库历史
                   source: 机台入库
```

### 方式2：自动入库（逻辑入库）

```
生产完成 → 待入库 → [配货操作] → 待发货 → [出库] → 已出库
                      ↑
                   记录入库历史
                   source: 直接配货-自动入库 / 配货自动入库
```

## 💡 业务场景示例

### 场景A：紧急订单（使用直接配货-自动入库）

1. **生产完成**：机台状态为"待入库"
2. **接到紧急订单**：客户要求立即发货
3. **直接配货**：在订单管理中直接将"待入库"机台分配给订单
4. **自动入库**：系统自动记录入库历史，状态变为"待发货"
5. **立即出库**：跳过物理入库环节，直接发货

**优势**：节省时间，快速响应

### 场景B：计划性配货（使用配货自动入库）

1. **生产完成**：多台机台状态为"待入库"
2. **生产计划配货**：在生产计划模块为订单分配机台
3. **配货完成**：所有需求机型都已分配
4. **自动入库**：点击"完成配货"，系统自动记录"待入库"机台的入库历史
5. **等待出库**：机台状态变为"待发货"，等待发货时间

**优势**：批量处理，计划性强

### 场景C：常规入库（使用手动入库）

1. **生产完成**：机台状态为"待入库"
2. **物理入库**：仓库人员扫码，放入指定库位
3. **记录入库**：系统记录入库历史，状态变为"库存中（A01）"
4. **后续配货**：根据订单需求，从库存中配货
5. **配货时不记录入库**：因为已经有入库记录了

**优势**：规范管理，便于盘点

## ⚠️ 注意事项

### 1. 自动入库不会重复记录

如果机台已经是"库存中"状态，配货时**不会**再次记录入库历史：

```python
# 配货的机台中
allocated_serials = ["SN001", "SN002", "SN003"]

# 当前状态
SN001: 待入库    ✅ 会记录入库历史
SN002: 库存中    ❌ 不会记录（已有入库记录）
SN003: 待发货    ❌ 不会记录（已配货过）

# 结果：只有 SN001 会被记录到 inbound_history 表
```

### 2. 自动入库没有库位信息

自动入库时，`slot_code`（库位）字段为空：

```python
record_inbound_history(
    conn,
    pending_inbound_serials,
    source="配货自动入库",
    slot_code="",              # 没有库位信息
    status_after="待发货"       # 直接变为待发货
)
```

这是因为机台跳过了物理入库环节，没有实际放入库位。

### 3. 自动入库的入库时间

自动入库的入库时间 = 配货操作的时间：

```python
inbound_time = datetime.now()  # 配货时的时间
```

这反映了机台**逻辑上进入库存系统**的时刻。

## 🔍 常见问题

### Q1: 为什么需要自动入库？
**A**: 
- 提高效率：紧急订单可以跳过物理入库环节
- 灵活性：支持直发、直配等业务场景
- 准确性：确保所有入库都有历史记录

### Q2: 自动入库和手动入库有什么区别？
**A**:
- **手动入库**：物理入库，有库位信息，状态变为"库存中（库位）"
- **自动入库**：逻辑入库，无库位信息，状态直接变为"待发货"

### Q3: 如何判断一台机器是手动入库还是自动入库？
**A**: 查看 `inbound_history` 表的 `source` 字段：
- `机台入库`：手动入库
- `直接配货-自动入库`：订单直接配货触发
- `配货自动入库`：生产计划配货触发

### Q4: 配货时如何知道哪些机台会触发自动入库？
**A**: 系统会自动检测：
- 状态为"待入库"的机台 → 触发自动入库
- 状态为"库存中"的机台 → 不触发（已有入库记录）

### Q5: 自动入库后还能看到入库记录吗？
**A**: 可以！入库报表会显示所有入库记录，包括自动入库：
```
流水号    入库日期      状态      来源
SN001    2026-05-30   待发货    配货自动入库
SN002    2026-05-29   库存中    机台入库
```

## 📝 开发者指南

### 如何添加新的自动入库场景

如果需要在新的业务场景中支持自动入库：

```python
# 1. 获取配货的机台
allocated_serials = [...]

# 2. 筛选出"待入库"状态的机台
pending_inbound = [
    sn for sn in allocated_serials
    if get_status(sn) == "待入库"
]

# 3. 更新状态
update_status(allocated_serials, "待发货")

# 4. 记录入库历史（只记录待入库的）
if pending_inbound:
    record_inbound_history(
        conn,
        pending_inbound,
        source="你的场景名称-自动入库",
        operator=operator,
        status_before="待入库",
        status_after="待发货"
    )
```

### 测试自动入库功能

```python

create_machine(serial_no="TEST001", status="待入库")

# 执行配货操作
allocate_inventory(
    order_id="SO-001",
```
