# 生产需求趋势预测模块：功能解析与说明

> 文档状态：功能分析稿
>
> 编制日期：2026-10-08
>
> 适用系统：V8BetaV1.1 成品、订单、库存与生产管理系统
>
> 说明：本文档基于现有系统结构和业务数据进行功能解析，不等同于已经完成开发的功能清单。文中标记为“待确认”的内容，需要结合实际业务口径和生产现场数据进一步确认。

---

## 1. 功能定位

生产需求趋势预测模块用于基于历史销售数量、实际出库/交付数量、实际入库数量、库存、有效订单和排产数据，预测未来指定时间段内各产品型号的需求，并计算建议新增生产量。

模块的核心目标不是直接替代 MRP，也不是直接生成不可修改的生产指令，而是形成以下决策链：

```text
历史销售/出库数量
        +
有效订单需求
        +
实际入库与库存变化
        +
在制品及已排产数据
        ↓
销售需求趋势预测
        ↓
库存与订单净化
        ↓
建议新增生产量
        ↓
人工调整与确认
        ↓
现有预测沙盘
        ↓
批次/产线安排
        ↓
生产看板执行
        ↓
实际结果回填
        ↓
预测准确率评估
```

### 1.1 模块解决的问题

模块主要回答以下问题：

1. 未来某个月、某个机型可能需要多少台？
2. 当前销售需求是否持续超过实际入库/生产供给？
3. 当前库存、在制品和已排产数量能否覆盖未来需求？
4. 未来还需要新增生产多少台？
5. 计划员为什么修改了系统建议？
6. 预测结束后，系统预测与实际销售、出库、入库结果相差多少？

### 1.2 模块不直接解决的问题

第一版不应直接承担以下职责：

- 代替 MRP 进行 BOM 展开；
- 自动生成采购订单；
- 自动替代生产计划员确认最终排产；
- 自动判断所有异常订单是否属于正常市场需求；
- 在缺少可靠历史数据时生成看似精确的预测结果；
- 将统计预测直接写入生产执行数据并覆盖原始计划。

### 2.2 与现有预测沙盘的边界

当前“预测沙盘”更接近订单、机型比例和产线安排驱动的批次规划，不等同于基于历史销售数量的统计预测。

建议明确区分：

| 名称 | 含义 |
|---|---|
| 需求趋势预测 | 根据历史销售/出库数量和有效订单预测未来需求 |
| 生产建议 | 扣除库存、在制品和已排产后的建议新增生产量 |
| 预测沙盘 | 将建议数量转换为机型比例、批次和产线安排 |
| 生产看板 | 展示已经确认的计划和实际执行状态 |

## 3. 重要业务口径

### 3.1 销售数量、订单数量和出库数量必须分开

本模块的核心修正是：预测基础使用“销售数量”，而不是销售金额。

但是以下概念仍不能混用：

```text
销售数量 ≠ 销售订单数量
销售数量 ≠ 实际出库数量
销售数量 ≠ 实际交付数量
销售数量 ≠ 实际生产数量
实际生产数量 ≠ 成品入库数量
```

建议在系统中分别保留：

- 订单数量：客户下单或审核通过的需求量；
- 出库数量：仓库发生出库的数量；
- 交付数量：完成交付确认的数量；
- 入库数量：成品进入库存的数量；
- 完工数量：生产现场确认完成的数量；
- 销售数量：用于预测的需求事实口径。

如果当前没有独立的销售事实表，第一版可以将“实际出库/交付数量”作为销售需求的代理指标，但页面必须显示真实口径，不应把代理数据直接命名为销售数量。

### 3.2 销售数量与生产数量差异

销售数量和生产数量单位相同，因此可以比较：

```text
销售生产差额 = 销售数量 - 实际生产数量
```

但该差额不能直接等同于生产缺口，因为销售可能消耗期初库存，生产也可能尚未入库。

更完整的库存平衡关系为：

```text
期末库存
= 期初库存
+ 实际入库
- 实际出库/交付
± 库存调整
```

因此页面应同时展示：

- 销售数量；
- 实际出库/交付数量；
- 实际入库数量；
- 销售与入库差额；
- 期初库存；
- 期末库存；
- 库存变化趋势。

### 3.3 有效订单口径

不是所有订单都应进入预测需求。建议按照订单状态分层：

| 订单状态 | 是否进入正式需求 | 说明 |
|---|---:|---|
| 草稿 | 否 | 尚未确认 |
| 待审核 | 否或单独展示 | 不能与正式需求混合 |
| 已审核/有效 | 是 | 进入已确认需求 |
| 已配货 | 是 | 进入已承诺需求，并同步扣除相关库存 |
| 已排产 | 是 | 进入承诺需求，但不能重复扣减排产量 |
| 已发货/已交付 | 从未交付需求中扣除 | 仍可作为历史销售事实 |
| 已取消/已释放 | 否 | 应排除 |

### 3.4 实际生产与实际入库

当前系统已经有实际入库日志和入库历史。现阶段可以将有效成品入库作为供给侧事实，但必须明确：

```text
实际入库数量 = 当前可用的生产完成代理指标
```

不能无条件称为“实际生产数量”，因为生产完成和成品入库之间可能存在时间差。

当前完工/入库相关报表逻辑位于：

```text
crud/reports.py
```

其中实际入库报表已经按照有效入库事件、首次事件和当前状态进行筛选。该逻辑可以作为预测模块的供给事实来源，但需要在接口字段中保留“入库口径”和“日志来源”。

| 数据内容 | 当前主要来源 | 预测用途 |

| 销售订单 | `sales_orders` | 已确认订单、需求机型、数量和时间 |
| 工厂计划 | `factory_plan` | 已排产数量、要求交期和计划状态 |
| 成品历史 | `shipping_history` | 历史出库/成品状态，具体口径需确认 |
| 入库操作 | `transaction_log` | 自动入库及相关历史事件 |
| 人工业务日志 | `sys_operation_log` | 人工入库和业务操作事件 |
| 入库历史 | `inbound_history` | 统一的有效入库事实 |
| 产品字典 | `model_dictionary` | 机型、系列、大类和排序 |
| 生产执行 | 生产看板及沙盘相关数据 | 在制品、生产线、批次和执行状态 |

### 4.2 第一版推荐预测粒度

第一版建议固定为：

```text
机型 + 月份
```

可以同时向上汇总到：

```text
产品系列 + 月份
产品类别 + 月份
公司整体 + 月份
```

第一版暂不建议强制加入以下维度：

- 客户区域；
- 经销商；
- 产品等级；
- 机床规格；
- 客户行业；
- 新老产品。

这些维度只有在数据完整、编码稳定并且业务规则明确后再增加。

## 5. 核心计算逻辑

### 5.1 历史需求事实

按照机型和月份统计：

```text
历史销售/出库数量
历史有效订单数量
历史实际交付数量
历史实际入库数量
期初库存
期末库存
```

需要避免同一台成品、同一订单或同一条日志被重复计算。

### 5.2 基础需求预测

第一版可采用历史同期加权平均：

```text
基础预测
= 去异常后的历史同期需求 × 对应权重之和
```

示例：

```text
2024 年 3 月：80 台，权重 20%
2025 年 3 月：100 台，权重 30%
2026 年 3 月：120 台，权重 50%

2027 年 3 月基础预测
= 80 × 20% + 100 × 30% + 120 × 50%
= 106 台
```

要求：

- 样本不足时标记数据不足；
- 不应将缺失月份默认当成 0；
- 需要区分停产、断货和真实零销量；
- 一次性大订单应允许标记并参与异常处理。

### 5.3 趋势和季节性

可以在基础预测上增加趋势和季节性，但不建议第一版简单地将所有修正项连续相乘，以免重复放大趋势。

建议采用可解释的结构：

```text
统计需求预测
= 历史同期基础需求
+ 趋势增量
+ 季节增量
```

或者分别计算以下模型后进行回测选择：

```text
模型 A：历史同期加权平均
模型 B：移动平均
模型 C：趋势模型
模型 D：趋势 + 季节模型
```

### 5.4 预测总需求

预测总需求不能简单等于“统计预测 + 全部订单”，否则会重复计算。

建议：

```text
预测总需求
= 有效订单中尚未交付部分
+ 未被有效订单覆盖的统计需求
```

如果业务暂时无法完成订单与历史销售的去重，第一版可以将二者并列展示，不直接合成为一个最终数字，并标记为“需人工确认”。

### 5.5 建议新增生产量

建议新增生产量的核心公式：

```text
建议新增生产量
= 预测总需求
+ 目标期末安全库存
- 当前可用库存
- 可确认在制品
- 已排产未完成数量
- 已确认可用外部供给
```

结果小于 0 时：

```text
建议新增生产量 = 0
```

但需要额外展示库存富余：

```text
预计库存富余 = -原始净需求
```

### 5.6 库存口径

不能把 `finished_goods_data` 中的所有记录直接作为可用库存。

建议区分：

```text
账面库存
可用库存
已占用库存
待入库
已发货
已锁定
异常库存
```

用于计算建议新增生产量的应当是：

```text
可用库存
= 状态有效
且未被有效订单占用
且未发货
且不属于待入库
且符合业务可供货规则
```

至少支持显示：

- 历史有效订单数量；
- 预测需求；

- 实际库存；
- 预测区间；

建议使用不同颜色区分：

```text

预测区间：浅色带状区域
```

### 6.5 人工调整

系统允许计划员修改建议值，但不能覆盖原始预测。

调整记录至少包括：

```text
系统预测值
系统建议生产值
人工调整值
调整人员
调整时间
调整原因
补充说明
```

建议原因：

- 已知大客户订单取消；
- 一次性订单；
- 原材料不足；
- 产能不足；
- 机型停产；
- 产品切换；
- 市场变化；
- 库存数据异常；
- 其他。

## 7. 预测区间与数据质量

第一版不建议直接展示没有计算依据的“置信度 82%”。

更适合展示：

```text
数据质量：高 / 中 / 低
预测稳定性：高 / 中 / 低
历史样本数：36 个月
最近 12 个月 WAPE：8.6%
预测区间：105～135 台
```

数据质量可参考以下因素：

- 历史样本数量；
- 数据完整率；
- 机型名称是否稳定；
- 缺失月份数量；
- 异常订单数量；
- 需求波动程度；
- 是否为新产品；
- 是否为停产产品；
- 最近周期预测误差。

### 7.1 误差指标

MAPE 在实际值为 0 时会失效，因此不能单独使用。

建议使用：

```text
MAE  = 平均绝对误差
WAPE = 总绝对误差 / 实际数量总和
Bias = 预测值与实际值的长期偏差
MAPE = 仅在实际数量大于 0 时计算
```

第一版至少展示：

- MAE；
- WAPE；
- Bias；
- 有效样本数。

## 8. 预测结果追踪

每一次预测都应保存版本和生成时的输入快照，不能只保存最终数字。

建议保存以下信息：

```text
预测月份
机型
产品系列
预测方法
模型版本
历史样本数
统计预测值
有效订单需求
预测总需求
可用库存
在制品
已排产数量
建议新增生产量
预测区间
数据质量
生成人员
生成时间
```

预测周期结束后回填：

```text
实际销售/出库数量
实际交付数量
实际入库数量
实际期末库存
实际完成生产计划
MAE
WAPE
Bias
```

这样才能回答：

> 系统预测是否准确？
>
> 误差来自需求判断，还是来自库存/产能约束？
>
> 计划员调整后是否比系统原始建议更好？


字段是否全部落地，需要根据当前真实数据源确认。没有可靠来源的字段不应先伪造。

## 10. 分阶段实施建议

### 阶段一：历史趋势分析

目标：先把历史事实和数据口径做对。

实现内容：

- 机型/月度历史销售或出库汇总；
- 实际入库数量汇总；
- 有效订单数量汇总；
- 期初、期末库存；
- 销售与入库差额；
- 趋势图；
- 数据质量提示。

阶段一不直接生成正式生产计划。

### 阶段二：统计需求预测

实现内容：

- 历史同期加权平均；
- 移动平均；
- 简单趋势模型；
- 季节性指数；
- 异常值标记；
- 预测区间；
- 模型回测。

### 阶段三：生产建议

实现内容：

- 当前可用库存扣减；
- 有效订单净化；
- 在制品扣减；
- 已排产未完成扣减；
- 安全库存；
- 建议新增生产量；
- 人工调整与原因记录。

### 阶段四：接入预测沙盘

将“建议新增生产量”传给当前预测沙盘，由沙盘继续处理：

- 机型比例；
- 预测批次；
- 产线安排；
- 计划员调整；
- 批次确认。

统计预测值、生产建议值和沙盘确认值必须分别保留。

### 阶段五：结果回算

预测月份结束后自动或手动回填：

- 实际销售/出库数量；
- 实际交付数量；
- 实际入库数量；
- 实际库存；
- 预测误差；
- 人工调整效果。

## 11. 第一版验收标准

### 数据准确性

- 同一成品不会因多条日志重复统计；
- 已取消、已释放和无效订单不会进入正式需求；
- 待入库、已发货和被占用库存不会错误计入可用库存；
- 缺失月份不会被自动当作零销量；
- 机型字典变化可以追溯；
- 实际销售、出库、入库和生产口径在页面上明确展示。

### 计算正确性

- 预测需求和建议新增生产量分别显示；
- 有效订单与历史销售不会重复相加；
- 库存、在制品、已排产数量扣减逻辑清晰；
- 建议新增生产量不会出现负数，但库存富余能够展示；
- 实际值为 0 时不会导致 MAPE 计算错误；
- 历史样本不足时不生成虚假的高精度结果。

### 可追溯性

- 每次预测保存生成时间和预测方法；
- 每次预测保存模型版本；
- 人工调整不覆盖原始预测；
- 人工调整保存人员、时间和原因；
- 预测结束后可以查看实际结果和误差。

### 与现有系统衔接

- 可以跳转或传递到当前预测沙盘；
- 统计预测值不直接覆盖沙盘确认值；
- 沙盘确认结果能够回溯到原始趋势预测；
- 生产看板能够区分建议计划和已确认计划。

## 12. 当前需要业务确认的问题

在正式开发之前，需要确认以下问题：

1. 系统中的“销售数量”以实际出库、实际交付，还是订单完成量为准？
2. `shipping_history` 的业务含义到底是出货、交付，还是库存流转？
3. 当前是否存在独立、完整的生产完工记录？
4. 如果没有生产完工记录，是否允许使用有效入库数量作为生产完成代理？
5. 在制品数据目前存储在哪里？是否包含预计完成时间？
6. `factory_plan` 中的排产数量是否能区分已完成和未完成？
7. 已配货但未发货的库存是否视为订单专用库存？
8. 经销商订单审核前后，分别如何进入需求统计？
9. 新产品、停产产品和机型改名如何建立历史映射？
10. 安全库存按机型、系列还是公司统一配置？
11. 预测结果是否需要经过计划员确认后才能进入预测沙盘？
12. 是否允许按机型人工修改安全库存和异常标记？

## 13. 最终建议

当前最适合 V8 系统的实现路径是：

```text
销售/出库历史事实
        ↓
机型月度需求趋势
        ↓
统计销售需求预测
        ↓
叠加有效订单并避免重复计算
        ↓
扣除可用库存、在制品和已排产
        ↓
生成建议新增生产量
        ↓
计划员调整并记录原因
        ↓
进入现有预测沙盘
        ↓
形成批次和产线安排
        ↓
进入生产看板
        ↓
实际结果回填
        ↓
预测误差分析
```

第一版的重点不是引入复杂算法，而是先保证以下三点：

1. **销售数量的来源可靠；**
2. **销售、订单、库存、入库和生产口径不混淆；**
3. **系统预测、人工调整、沙盘确认和实际结果可以完整追踪。**

只要这三点建立起来，后续增加 Holt-Winters、ARIMA、产能约束和 MRP 联动才有可靠基础。
