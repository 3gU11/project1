# 入库历史数据保存机制

## 📋 概述

系统使用 `inbound_history` 表作为**不可变的历史事件表**，记录所有入库操作。这确保了报表数据的准确性和可追溯性。

---

## 🔄 自动记录机制

系统在以下场景会**自动记录**入库历史，无需手动干预：

### 1. 手动入库
- **触发位置**: 仓库管理 → 机台入库
- **代码位置**: `crud/inventory.py:549` 和 `crud/inventory.py:651`
- **source标识**: `机台入库`
- **记录内容**:
  - 流水号、批次号、机型
  - 入库时间、操作员
  - 库位（Location_Code）
  - 状态变化：`待入库` → `库存中（库位）`
  - 客户、代理商、订单号等

### 2. 直接配货自动入库
- **触发位置**: 订单管理 → 直接配货
- **代码位置**: `crud/orders.py:265`
- **source标识**: `直接配货-自动入库`
- **说明**: 当订单直接配货时，状态为"待入库"的机台会自动入库并变为"待发货"

### 3. 配货自动入库
- **触发位置**: 生产计划 → 订单配货
- **代码位置**: `api/routes/planning.py:1212`
- **source标识**: `配货自动入库`
- **说明**: 订单配货时，待入库机台自动入库

### 4. 库存调拨
- **说明**: 调拨操作（`is_transfer=True`）**不会**记录入库历史
- **原因**: 调拨只是库位变更，不是新的入库事件

## 📊 数据结构

### inbound_history 表字段

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT | 主键，自增 |
| serial_no | VARCHAR(100) | 流水号 |
| inbound_time | DATETIME | 入库时间 |
| source | VARCHAR(50) | 入库来源（机台入库/配货自动入库等） |
| slot_code | VARCHAR(100) | 库位代码 |
| operator | VARCHAR(100) | 操作员 |
| batch_no | VARCHAR(100) | 批次号 |
| model | VARCHAR(255) | 机型 |
| customer | VARCHAR(255) | 客户 |
| dealer | VARCHAR(255) | 代理商 |
| contract_no | VARCHAR(100) | 合同号 |
| order_no | VARCHAR(100) | 订单号 |
| status_before | VARCHAR(50) | 入库前状态 |
| status_after | VARCHAR(50) | 入库后状态 |
| created_at | TIMESTAMP | 记录创建时间 |

### 索引设计

```sql
-- 唯一索引：防止重复记录同一入库事件
UNIQUE KEY uk_inbound_history_event (serial_no, inbound_time, source)

-- 查询优化索引
INDEX idx_inbound_history_time (inbound_time)
INDEX idx_inbound_history_serial (serial_no)
INDEX idx_inbound_history_batch (batch_no)
INDEX idx_inbound_history_model (model)
INDEX idx_inbound_history_customer (customer)
```

- 支持重复执行（使用 INSERT IGNORE）

### 回填逻辑说明

回填函数会从 `transaction_log` 表中提取符合以下条件的记录：

1. **操作类型匹配**:
   - `直接配货-自动入库`
   - `配货自动入库`
   - 包含"入库"关键字的操作（排除退回、释放、撤回）

2. **状态过滤**:
   - 排除 `status_after = '待入库'`
   - 排除 `status_after = ''`（空状态）

3. **数据来源**:
   - 优先从 `finished_goods_data` 获取当前数据
   - 如果已出库，从 `shipping_history` 获取历史数据

## ⚠️ 注意事项

### 1. 数据不可变性
- `inbound_history` 是历史事件表，记录后**不应修改或删除**
- 如果需要更正，应该记录新的事件，而不是修改旧记录

### 2. 重复记录防护
- 唯一索引 `uk_inbound_history_event` 防止同一事件重复记录
- 使用 `INSERT IGNORE` 确保回填操作可以安全重复执行

### 3. 状态过滤
- 报表查询会自动排除"待入库"和空状态的记录
- 使用 `COALESCE` 处理NULL值，确保过滤逻辑正确

### 4. 性能优化
- 已建立时间、流水号、批次号等索引
- 大批量回填建议在业务低峰期执行

## 🔍 常见问题

### Q1: 为什么报表数据和当前库存不一致？
**A**: 这是正常的。入库报表统计的是**历史入库事件**，而当前库存反映的是**当前状态**。已入库后又出库的机器会出现在入库报表中，但不在当前库存中。

### Q2: 调拨操作会记录入库历史吗？
**A**: 不会。调拨（`is_transfer=True`）只是库位变更，不是新的入库事件，因此不会记录到 `inbound_history` 表。

### Q3: 如何验证历史数据回填是否成功？
**A**: 
1. 检查回填前后的记录数变化
2. 查看统计信息中各来源的记录数和日期范围
3. 生成入库报表，验证历史数据是否完整

### Q4: 可以多次执行回填吗？
**A**: 可以。使用了 `INSERT IGNORE`，重复的记录会被自动跳过，不会产生重复数据。

## 📝 开发者指南

### 添加新的入库场景

如果需要在新的业务场景中记录入库历史：

```python
from crud.inbound_history import record_inbound_history

# 在入库操作的事务中调用
with get_engine().begin() as conn:
    # ... 执行入库操作 ...
    
    # 记录入库历史
    record_inbound_history(
        conn,
        serial_nos=[serial_no],  # 流水号列表
        source="你的场景名称",     # 入库来源标识
        operator=operator_name,   # 操作员
        slot_code=slot_code,      # 库位（可选）
        inbound_time=datetime.now(),  # 入库时间（可选，默认当前时间）
        status_before=old_status,     # 入库前状态
        status_after=new_status,      # 入库后状态
    )
```

### 查询入库历史

```python
from sqlalchemy import text
from database import get_engine

with get_engine().connect() as conn:
    result = conn.execute(text("""
        SELECT * FROM inbound_history
        WHERE serial_no = :sn
        ORDER BY inbound_time DESC
    """), {"sn": "your_serial_no"})
    
    for row in result:
        print(f"{row.inbound_time}: {row.source} by {row.operator}")
```
