# 维修系统机台零部件只读接口（2026-11-04）

## 1. 用途

售后人员在 mobile 端按机型拍照清单逐项拍照/OCR，手工确认后由 V8 写入
`machine_component_bindings`（机台-位置-零部件编号绑定，记录拍照任务、识别值、
置信度、审核人等信息）。维修系统通过本接口按机台流水号只读查询这台机器上实际
收集到的零部件信息，用于维修核对待更换部件、编号追溯。

**只读**：接口只做 `SELECT`，不写库、不触发拍照任务或状态回传。

## 2. 接口

```http
GET /api/v1/repair-machine-components?machineNo=96-06-234[&includeInactive=true]
X-V8-API-KEY: {REPAIR_IDENTITY_API_KEY}
```

| 参数 | 位置 | 必填 | 说明 |
| --- | --- | --- | --- |
| `machineNo` | query | 是 | V8 机台流水号，最长 150 字符 |
| `includeInactive` | query | 否 | 默认 `false` 只返回当前有效（`active=1`）的零部件；传 `true` 时附带已替换/失效的历史绑定 |
| `X-V8-API-KEY` | header | 是 | V8 服务身份密钥，与 `/api/v1/repair-identity`、`/api/v1/repair-model-components` 共用同一把 |

### 3.1 字段口径

| 字段 | 说明 |
| --- | --- |
| `machineNo` / `modelName` / `machineBatchNo` | 机台流水号、机型、生产批次号 |
| `machineStatus` / `customerName` / `agent` / `locationCode` / `deliveryDate` / `outboundAt` | 绑定行上的机台状态与出货信息，空值返回空串 |
| `components[]` | 拍照任务收集到的零部件（按 `positionCode` 排序，`active` 在前） |
| `positionCode` / `positionName` | 拍照位置编码 / 位置名称（如 `SN-CPU`、`SN-MOTOR`） |
| `componentSerialNo` | 零部件自身编号（照片 OCR 结果或人工确认值） |
| `materialCode` | 完整物料编码：`位置前缀-零部件编号`，与 `/api/v1/repair-identity` 的口径一致；缺少任一值时为 `""` |
| `materialName` / `materialType` / `materialSpec` | 位置对应的物料名称、类别、规格（来自拍照项目库配置） |
| `active` | 当前是否仍绑定在该机台上；`false` 表示已被替换 / 失效 |
| `boundAt` | 该零部件绑定到机台的日期 |
| `photoTaskId` / `photoTaskStatus` / `submitBatch` | 来源拍照任务 ID、任务状态（如 `manual_passed` / `completed`）、提交批次 |
| `photoFileName` | 来源照片文件名（仅文件名，不返回图片二进制；需要图片可另行增加下载接口） |
| `recognizedValue` / `manualValue` / `confidence` | OCR 识别值、人工确认值、识别置信度（无值时为 `null`） |
| `checkStatus` / `reviewedBy` / `reviewedAt` | 识别结果审核状态、审核人、审核时间 |
| `source` / `updatedAt` | 绑定来源（如 `V8_OCR`）、绑定行最后更新时间 |
| `sourceVersion` | 投影版本号，取返回行的最大 `updated_at`，便于维修侧判断是否需要刷新缓存 |

## 4. 状态码约定

| 状态码 | 含义 |
| --- | --- |
| `200` | 查询成功；机台存在绑定历史但当前无有效零部件时 `components` 为空数组、`componentCount=0` |
| `404` | 该机台在 V8 没有任何零部件绑定记录 |
| `401` | `X-V8-API-KEY` 缺失或不匹配 |
| `422` | `machineNo` 缺失/超长 |
| `503` | V8 未配置 `REPAIR_IDENTITY_API_KEY`，接口未启用 |

## 5. 配置与调用方约定

- V8 `.env` 中配置 `REPAIR_IDENTITY_API_KEY`（与维修身份、拍照清单接口共用同一把密钥），重启 FastAPI 后生效。
- 密钥只能放在维修系统服务端；**不得**写入小程序包、浏览器代码或前端环境变量。
- 建议维修服务端对同一机台结果做短缓存（如 60 秒），并用 `sourceVersion` 判断是否刷新。
