# 合同「需方 / 代理商」取值规则（2026-11-12）

## 1. 背景

「经销商订单转合同」后，合同头「需方」、工厂计划 / 销售订单 / 成品台账 / 入库发货历史里的
「代理商」曾出现客户联系人姓名（如订单 `DO1794190999130FC0F95` → 合同 `HT202611090002`
的代理商被写成客户联系人「熊廷艳」，客户是「厦门佳胜达科技有限公司」，实际大区经理是「陈利春」）。

根因有两处，都是把 `contact_name` 当成了代理商：

- 前端「经销商订单转合同」弹窗：`convertForm.agent = order.contact_name`；
- 后端转合同端点：`agent = payload.agent_name or items[0].contact_name`。

## 2. 取值规则（唯一口径）

统一由 `crud/local_contract_drafts.py:resolve_party_name` 决定，优先级：

1. **订单上记录的大区经理**（`dealer_orders.regional_manager_name`，云端字段 `regionalManagerName`）；
2. 没有可用大区经理时，退回**经销商公司名**（`dealer_orders.dealer_name`）；
3. 两者都没有就留空，按合同「缺项」由审批人补齐，不编造。

明确不使用：客户联系人 `contact_name`。人员注销后门户把姓名改成「已删除人员」，
这类占位值（`INVALID_PARTY_NAMES`）视为未填，继续退回经销商公司名。

### 为什么一个订单只会有一位经理（大区多经理也不歧义）

订单在提交时就把经理固化成一位：

- 经销商下单：订单记录该经销商归属的大区经理（`portal_user.regional_manager_id`）；
- 大区经理本人下单：记录的就是提交人。

所以**不按大区去「挑一位经理」**（同一大区有多个经理时会变成谁先谁后、谁在线谁负责的不确定逻辑），
只认订单上的这一位。合同附件「需方」与工厂计划的「代理商」共用同一口径，保证两处永远一致。

### 存量数据读取时自动纠正

`_normalize_stored_fields` 会把未归档草稿里「需方 = 经销商名 / 客户联系人 / 注销占位名」的旧值
重置为上面的口径；审批人手工改过的值不动。历史合同（已归档）不自动改，用下面的修复脚本回填。

## 3. 历史数据回填

```bash
# 预览
python ops/repair_contract_agent_names.py
# 备份（data_repair_backups/）后写入
python ops/repair_contract_agent_names.py --apply
```

只改「代理商 == 该订单客户联系人」或注销占位名的行，人工维护过的值不会被动到；
同时修 `factory_plan`、`sales_orders`、`finished_goods_data`、`contract_notifications`
快照、`shipping_history`、`inbound_history`。2026-11-12 首次执行回填了 14 张合同
（备份：`data_repair_backups/repair_agent_names_20261112_172626.json`）。
