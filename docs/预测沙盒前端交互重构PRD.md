## 2. 产品定位

预测沙盒不是 APS，也不承担全自动最优排程。

本产品定位为：在现有规则算法基础上，为 BOSS 和排产人员提供一个可理解、可调整、可预览、可确认、可追溯的辅助排产工作台。

系统负责：

1. 将合同按交期规则进入预测队列。
2. 根据 BOSS 设置的机型比例，对指定大类的未确认队列进行后移重排，并用备货建议补齐目标比例。
3. 允许人工处理急单、交期提前、交期延后和特殊机型。
4. 将预测方案与正式计划隔离，只有确认后的批次才能进入产线派工。
5. 已进入产线的合同允许在受控条件下进行线内调度，并展示调度影响。

## 3. 背景与问题

### 3.1 当前业务能力

现有系统已经具备以下基础能力：

- 合同按交期排序并进入预测批次。
- G、XS、AUTO 等机型族隔离排产。
- 按固定批次容量分批。
- 按机型比例生成备货占位。
- 维护预测批次、已确认批次和生产中批次。
- 支持全量重算、局部重算、批次确认、撤销确认、拖拽、急单、特殊卡片和产线派工。
- 已确认批次可分配至空闲产线，产线由人工选择。

### 3.2 当前核心问题

当前问题主要是业务阶段、操作后果和异常处理没有在界面上明确表达，而不是功能按钮不足。

| 编号 | 问题 | 业务风险 | 优先级 |
|---|---|---|---|
| P-01 | 需求、预测方案、已确认计划和产线执行混在同一工作区 | 新手无法判断当前处于哪个阶段 | P0 |
| P-02 | 重算、拖拽、急单等操作可能直接改变持久化数据 | 用户误以为是模拟，实际已改变正式结构 | P0 |
| P-03 | 预测批次与已确认批次同画布展示 | 容易误操作冻结计划 | P0 |
| P-04 | 结果只展示“排成什么样”，不解释“为什么” | BOSS 无法判断比例调整和交期风险 | P1 |
| P-05 | 确认后还需切换页面寻找可用产线 | 计划到执行存在认知断层 | P1 |
| P-06 | 备货占位与合同卡片视觉相似 | 备货建议可能被误认为客户承诺 | P1 |
| P-07 | 交期变化后的重排与线内调度入口不清晰 | 临时变化依赖熟练人员记忆和经验 | P0 |
| P-08 | 大量操作依赖拖拽和右键菜单 | 可发现性、可撤销性和键盘可用性弱 | P2 |

## 4. 重构目标

### 4.1 业务目标

1. 新用户首次进入页面即可理解“需求进入、生成方案、审核确认、派工执行”四个阶段。
2. BOSS 可以在不直接破坏正式计划的前提下调整机型比例并查看结果。
3. 排产人员可以识别所有未排合同及原因，处理交期变化和急单。
4. 已确认批次与生产中队列受到保护，普通重算不能覆盖。
5. 从已确认批次可以直接完成产线选择或进入派工页面。
6. 所有人工调整均有变更摘要、风险提示、操作者和时间记录。

### 4.2 用户体验目标

- 首屏明确显示当前阶段、待处理数量和下一步动作。
- 用户无需理解 `Predicted`、`Confirmed`、`In_Production` 等技术状态名。
- 任何会改变队列的操作，在提交前都能看到影响并撤销。
- 核心流程通过可见按钮完成，拖拽和右键菜单只作为快捷方式。

### 4.3 建议衡量指标

| 指标 | 目标 |
|---|---|
| 新用户完成“比例调整→生成方案→确认批次” | 无口头指导可完成 |
| 关键阶段识别正确率 | 100% |
| 未提交调整可撤销率 | 100% |
| 普通重算覆盖已确认/生产中数据 | 0 次 |
| 未排合同原因覆盖率 | 100% |
| 已确认批次到派工入口点击层级 | 不超过 2 次 |

## 5. 范围边界

### 5.1 第一阶段范围

- 重构预测沙盒信息架构和主流程。
- 重构预测方案视图和方案前后的模块衔接。
- 复用合同管理作为合同需求与待规划入口，不在预测沙盒复制需求池。
- 复用生产看板作为待排产、待派工、产线执行和线内调度入口，不在预测沙盒复制派工看板。
- 增加草稿方案和变更集交互。
- 增加比例调整、方案重算和影响摘要。
- 增加合同交期变更处理。
- 增加已确认批次跳转生产看板的上下文入口。
- 在预测方案中展示确认后的下一步说明，不复制生产看板的调度功能。
- 增加操作记录和失败反馈。
- 保留现有排产算法和主要接口能力，按需要增加解释性数据接口。

### 5.2 第一阶段不做

- 不引入新的 APS 排程引擎。
- 不自动替代 BOSS 的比例决策。
- 不把物料齐套、班次、维护窗口和换型时间作为强约束。
- 不自动在多条产线之间求全局最优解。
- 不删除现有预测、确认、派工和急单能力。
- 不允许无校验地修改已完工历史数据。

### 5.3 后续范围

- 物料齐套和库存约束。
- 班次、维护窗口和换型时间。
- 产线负荷优化与多目标权重。
- 方案版本对比、复制和长期归档。
- 更完整的甘特图和瓶颈分析。

## 7. 核心业务对象

| 对象 | 定义 | 关键字段 |
|---|---|---|
| 合同需求 | 需要进入计划的客户需求 | 合同号、客户、机型、机型大类、数量、要求交期、进入时间、备注 |
| 备货建议 | 为满足目标机型比例生成的非合同占位 | 机型、数量、来源比例、生成时间、可替换状态 |
| 预测批次 | 尚未确认、允许调整的计划批次 | 批次号、机型大类、容量、交期范围、合同数、备货数 |
| 方案草稿 | 一组尚未提交的预测批次与人工调整 | 方案 ID、版本、规则快照、变更集、指标、创建人 |
| 已确认批次 | 已冻结、等待派工的正式计划 | 确认人、确认时间、推荐产线、风险状态 |
| 产线任务 | 已分配到具体产线的执行队列 | 产线、顺序、预计开始/结束、执行状态 |
| 变更项 | 对方案或产线队列的一次未提交调整 | 类型、来源位置、目标位置、影响对象、风险 |
| 等待队列 | 暂时无法进入开放预测批次的需求 | 原因、进入时间、建议处理动作 |

## 8. 业务规则

### 8.1 合同进入规则

1. 合同以“要求交期升序”进入对应机型大类队列。
2. 要求交期相同的合同，按合同进入系统时间 FIFO。
3. 同一合同包含多台相同机型时，拆分为可进入批次槽位的生产单元，但界面默认聚合显示数量。
4. G、XS、AUTO、特殊等大类按现有机型字典和归类规则隔离。
5. 缺少交期、机型未启用、机型无法归类或开放批次容量不足时，不静默丢弃，进入等待队列并显示原因。
6. 普通合同不能自动插到已确认或生产中队列中。

### 8.2 比例调整规则

1. BOSS 选择一个机型大类后设置该大类内部各机型的目标比例。
2. 比例只作用于未确认的预测区，不改变已确认和生产中任务。
3. 合同需求优先保留，系统通过队列后移和备货建议补齐目标比例。
4. 比例调整不能使真实合同被删除；无法进入当前开放槽位的合同进入后续批次或等待队列。
5. 比例合计必须满足系统定义的合法范围；建议前端归一化显示并明确取整方式。
6. 每次计算记录比例快照、批次容量、断档阈值、开放槽位数和算法时间。

### 8.3 重排规则

1. 默认保留现有最早交期优先、固定容量分批、30 天交期断点、20 个预测槽位和等待队列规则。
2. “全量重算”只重建所有未确认预测批次。
3. “按大类重算”只重建选中大类的未确认预测批次。
4. 已锁定卡片在重算中受到保护；若原位置无法保留，必须进入冲突列表，不得静默移动或丢失。
5. 重算先生成草稿结果，用户点击“提交方案”后才写入正式预测结构。
6. 若后端暂时无法支持完整草稿持久化，第一阶段可使用前端临时变更集，但页面刷新前必须提示未提交内容会丢失。

### 8.4 合同交期变化规则

#### 交期提前

1. 系统标记为“需前移”，重新计算其在同大类队列中的建议位置。
2. 若目标位置属于预测批次，生成前移变更并展示被后移合同。
3. 若需要进入已确认批次或生产中队列，必须进入受控调度流程，不自动改动。
4. 无安全位置时进入风险列表，显示预计延期天数和建议动作。

#### 交期延后

1. 系统标记为“可后移”，给出释放近期产能的建议。
2. 预测区合同可在草稿中后移。
3. 已确认或生产中合同默认不自动后移，必须由有权限用户确认。
4. 后移后空出的槽位可由更早交期合同或备货建议补充。

#### 交期不变但数量/机型变化

1. 数量增加部分按新需求进入队列。
2. 数量减少优先释放未确认部分；涉及已确认或生产中部分时提示人工处理。
3. 机型变化视为原需求撤回并新增需求，必须重新校验机型大类和产线兼容性。

### 8.5 线内合同调度规则

1. 仅有线内调度权限的用户可操作。
2. 已进入产线的合同可执行同线前移、同线后移和兼容位置互换。
3. 第一阶段跨线调度通过“移出当前线→选择目标线→校验→提交”完成，不做无提示拖拽。
4. 调度前必须检查：机型兼容、锁定状态、目标位置、交期风险和被影响合同。
5. 加高、特殊或其他受限机型沿用现有限制；不满足条件时显示具体原因。
6. 提交前显示：当前合同变化、被挤压合同、预计日期变化、受影响批次和风险等级。
7. 调度写入审计日志，并支持查看调度前后位置；已提交的生产调度不提供前端直接撤销，需走反向调度。

## 9. 状态模型

### 9.1 用户可见业务阶段

```text
待规划需求 → 方案草稿 → 待确认方案 → 已确认待派工 → 生产中 → 已完成
                    ↘ 等待队列 / 冲突待处理
```

### 9.2 与现有技术状态映射

| 用户可见状态 | 现有状态/来源 | 是否允许普通重算 | 是否允许人工调整 |
|---|---|---:|---:|
| 待规划 | 合同数据、未排需求 | 是 | 是 |
| 方案草稿 | 新增交互态或方案版本 | 是 | 是 |
| 待确认 | `Predicted` | 是 | 是 |
| 已确认待派工 | `Confirmed` 且未绑定产线 | 否 | 仅撤销确认后 |
| 生产中 | `In_Production` | 否 | 仅线内调度流程 |
| 已完成 | 产线完成/入库状态 | 否 | 否 |

### 9.3 状态保护

- 普通重算只处理待规划、草稿和 `Predicted` 数据。
- `Confirmed`、`In_Production` 和已完成数据不得被普通重算覆盖。
- 撤销确认必须检查批次是否已派工；已派工批次不能直接退回预测状态。
- 所有跨阶段操作使用二次确认，并显示后果而不是只显示“确定/取消”。

## 10. 信息架构

预测沙盒采用一个预测方案工作台、两个跨模块入口和一个全局变更中心。合同需求和产线执行沿用系统现有模块，预测沙盒不重复承载。

```text
系统排产链路
├─ 合同管理（上游：合同录入、审核、交期）
├─ 预测沙盒（本模块：比例、预测队列、备货、批次确认前调整）
├─ 生产看板（下游：待排产、派工、产线执行、线内调度）
└─ 变更中心
   ├─ 未提交变更
   ├─ 冲突与风险
   └─ 操作记录
```

### 10.1 全局顶部区

预测沙盒固定展示：

- 当前模块与模块职责说明。
- 数据更新时间和服务状态。
- 当前方案名称、创建人、创建时间和未提交变更数。
- 合同台数、备货台数、延期合同数、等待队列数、已确认待派工数。
- 上游“合同管理”和下游“生产看板”入口；不在本模块重复展示合同录入或产线派工操作。

### 10.2 新手引导

- 第一次进入显示三模块链路引导：合同管理 → 预测沙盒 → 生产看板，可跳过并在帮助入口重新打开。
- 空状态必须说明原因和下一步按钮。
- 危险操作使用业务语言，例如“重新计算未确认方案”，不直接使用“全量重算”。
- 页面只保留一个主按钮，其他操作进入次级菜单或选中操作栏。

## 11. 页面与功能需求

### 11.1 页面一：待规划需求

#### 页面目标

让用户先看清有哪些合同、哪些尚未进入方案、为什么未排，再决定生成方案。

#### 页面结构

- 左侧：筛选条件。
- 中部：合同需求表格。
- 右侧：等待队列与异常原因。
- 顶部：需求统计和“生成预测方案”。

#### 列表字段

| 字段 | 说明 |
|---|---|
| 合同号 | 支持搜索和打开详情 |
| 客户 | 客户名称 |
| 机型/大类 | 原始机型与归类结果 |
| 数量 | 总数、已排数、未排数 |
| 要求交期 | 可显示近期、临期、逾期标识 |
| 进入时间 | 同交期 FIFO 的排序依据 |
| 当前去向 | 未排、预测批次、已确认、产线 |
| 风险 | 缺少交期、机型无效、容量不足等 |

#### 关键操作

- 按交期、机型大类、客户、风险筛选。
- 查看合同详情和历史变更。
- 查看未排原因和建议动作。
- 选择大类后生成方案。
- 对异常合同进行“补充交期”“修正机型”“加入特殊队列”等操作。

### 11.2 页面二：预测方案

#### 页面目标

让 BOSS 和排产员调整比例、查看重排结果、处理冲突并提交方案。

#### 页面结构

1. 方案摘要区。
2. 大类切换区。
3. 比例参数抽屉。
4. 批次视图/时间轴视图切换。
5. 选中对象操作栏。
6. 右侧变更与风险面板。

#### 方案摘要

至少展示：

- 合同台数。
- 备货台数。
- 合同按期覆盖率。
- 延期合同数量及最大延期天数。
- 等待队列数量。
- 当前大类的目标比例与实际比例。
- 已锁定对象数量。
- 本次重排影响的批次和合同数量。

#### 比例参数

- 先选择机型大类，再显示该大类下可参与比例计算的机型。
- 输入目标比例后即时展示合计、归一化结果和预计备货变化。
- 点击“预览重排”后生成草稿，不直接提交。
- 显示当前比例、目标比例和重排后的预计比例。
- 对比例取整造成的偏差给出说明。

#### 批次视图

每个批次显示：

- 批次类型和状态。
- 合同数量、备货数量、空槽数量和总容量。
- 交期范围和预计入库时间。
- 机型组成及实际比例。
- 形成原因：交期断点、容量满批、比例补齐、人工创建等。
- 风险：延期、锁定冲突、机型异常、等待队列溢出等。

合同卡和备货卡必须使用明显不同的视觉样式。备货卡显示“备货建议”及其来源比例，并标明可被合同替换。

#### 时间轴视图

- 按日期展示预测批次和交期分布。
- 第一阶段可只展示批次级时间轴，不要求完整甘特图。
- 标出近期交期、预计延期、空档和待派工节点。
- 点击批次可与批次视图联动。

#### 调整方式

- 拖拽卡片。
- 选中后执行“前移”“后移”“移动到批次”“锁定”“转急单”。
- 批量选择合同后移动。
- 任何调整先加入变更集，不立即提交。
- 支持撤销最近一次、重做和清空未提交变更。

### 11.3 变更预览与提交

#### 变更摘要

提交前必须显示：

| 指标 | 示例 |
|---|---|
| 受影响合同 | 12 台 |
| 受影响批次 | 3 个 |
| 新增延期 | 1 个合同，2 台 |
| 延期减少 | 2 个合同，3 台 |
| 备货变化 | +5 台 |
| 等待队列变化 | +1 台 |
| 锁定冲突 | 0 |

#### 提交闸门

提交前依次校验：

1. 机型大类兼容。
2. 批次容量。
3. 锁定对象保护。
4. 交期风险。
5. 已确认和生产中数据保护。
6. 方案数据版本是否已过期。

存在阻断错误时禁止提交；存在非阻断风险时要求填写调整原因。

#### 提交结果

- 成功：生成正式待确认方案，并显示方案编号、提交人和提交时间。
- 数据已变化：提示刷新并重新比较，不自动覆盖他人修改。
- 部分失败：整体回滚，列出失败对象和原因。
- 服务异常：保留本地草稿并允许重试。

### 11.4 页面三：已确认待派工

#### 页面目标

将已冻结的计划清晰交接给产线执行。

#### 页面内容

- 已确认批次列表。
- 批次交期、预计开始/结束、容量、合同数、备货数和风险。
- 推荐产线、可用产线和不可用原因。
- 当前产线负荷概览。

#### 关键操作

- 查看批次详情。
- 选择产线并派工。
- 查看派工预览。
- 在未派工前撤销确认。
- 已派工后跳转到对应产线。

#### 派工预览

至少显示：目标产线、当前任务、预计接续时间、兼容性、预计完工时间和交期风险。

### 11.5 页面四：产线执行

#### 页面目标

查看实际执行队列，并处理合同交期临时变化引起的线内调度。

#### 页面结构

- 左侧：产线列表与状态。
- 中部：选中产线的合同队列。
- 右侧：选中合同详情、交期变化和调度影响。

#### 关键操作

- 同线前移、后移和互换。
- 查看可插入位置。
- 将合同标记为急单。
- 发起跨线调度。
- 查看锁定原因和不可操作原因。
- 查看调度历史。

#### 调度预览

调度前展示调整前后队列，至少突出：

- 被调整合同的新位置。
- 被后移合同。
- 每个受影响合同的预计日期变化。
- 新增延期和风险等级。
- 是否需要 BOSS 或管理员二次确认。

## 12. 关键交互规则

### 12.1 主操作规则

| 阶段 | 主操作 |
|---|---|
| 待规划需求 | 生成预测方案 |
| 预测方案无变更 | 预览重排 |
| 预测方案有变更 | 提交方案 |
| 已确认待派工 | 分配产线 |
| 产线执行 | 提交调度 |

### 12.2 拖拽规则

- 拖拽开始时高亮合法目标，禁用目标显示原因。
- 放置后只生成变更项。
- 放置造成延期时立即显示风险提示，但不打断继续试排。
- 已确认和生产中对象不能拖入普通预测区。
- 键盘和按钮操作应具备与拖拽等价的能力。

### 12.3 错误与空状态

- 不使用“请求失败”“Go service error”等技术提示直接面向业务用户。
- 服务不可用时显示受影响模块、是否可继续查看、建议动作和重试按钮。
- 无批次时区分“尚未生成”“筛选无结果”“全部已确认”“服务加载失败”。
- 未排合同必须显示明确原因，不使用空白或通用未知状态。

### 12.4 未保存保护

- 切换大类、页签、路由或关闭页面时，如存在未提交变更，显示离开确认。
- 自动保存草稿时展示最近保存时间。
- 自动保存失败时保留本地变更并明确提示。

## 13. 数据与接口需求

### 13.1 优先复用的现有能力

- 批次列表、详情、确认和撤销确认。
- 全量/局部预测重算。
- 容量比例读取与更新。
- 单元移动、批次移动、槽位重排和内容互换。
- 急单插入、转急单和返回沙盒。
- 产线列表、派工、锁定和完工。

### 13.2 建议新增或扩展的数据

方案接口至少返回：

```json
{
  "plan_id": "PLAN-20260903-001",
  "version": 3,
  "status": "Draft",
  "created_at": "2026-09-03T14:30:00+08:00",
  "created_by": "admin",
  "rules": {
    "capacity": {"G": 30, "XS": 30, "AUTO": 27},
    "batch_break_days": 30,
    "max_open_batches": 20,
    "tie_breaker": "entered_at_fifo"
  },
  "metrics": {
    "contract_units": 22,
    "stock_units": 734,
    "late_contracts": 0,
    "queued_units": 0,
    "affected_batches": 3
  },
  "changes": [],
  "conflicts": []
}
```

合同需求需要补充或稳定提供：

- `entered_at`：同交期 FIFO 排序依据。
- `unscheduled_reason`：未排原因编码与说明。
- `current_stage`：当前业务阶段。
- `due_date_changed_at`：交期最近变更时间。
- `previous_due_date`：交期变更前值。

变更提交建议采用乐观锁：提交时携带方案版本；版本过期则返回冲突，不覆盖新数据。

### 13.3 审计日志

记录以下信息：

- 操作者、角色、操作时间。
- 操作类型和业务原因。
- 方案版本。
- 调整前后批次、产线和位置。
- 交期变化和风险结果。
- 提交成功或失败原因。

## 14. 非功能需求

### 14.1 性能

- 首屏骨架或摘要应在 2 秒内出现。
- 普通筛选和页签切换应在 300 毫秒内反馈。
- 重算超过 2 秒时显示明确进度状态，超过 30 秒允许用户离开后查看结果。
- 大量卡片默认聚合显示，避免一次渲染所有生产单元。

### 14.2 一致性

- 重算、提交和派工必须具备事务一致性。
- 部分失败不得留下半套方案。
- 页面显示的数据版本必须与提交时校验版本一致。

### 14.3 可用性与无障碍

- 核心操作不能仅依赖颜色、拖拽或右键。
- 状态同时使用文字和图标。
- 支持键盘选择、移动和确认关键操作。
- 危险按钮与普通按钮在位置、颜色和文案上区分。

### 14.4 可观测性

- 前端记录重算、提交、派工和调度失败的业务错误码。
- 后端日志可通过方案 ID、批次 ID、合同号和操作者关联查询。
- 服务状态区分 FastAPI、Go 沙盒和数据库依赖，避免统一显示为“系统错误”。

## 15. 验收标准

### 15.1 P0 验收

| 编号 | 验收场景 | 通过标准 |
|---|---|---|
| AC-01 | 首次进入预测沙盒 | 首屏可见四阶段导航、当前阶段说明、关键统计和下一步动作 |
| AC-02 | 生成预测方案 | 结果先进入草稿/待确认区，不直接进入产线 |
| AC-03 | 调整比例 | 只能作用于选中大类的未确认队列，已确认和生产中数据不变化 |
| AC-04 | 合同排序 | 按要求交期升序；同交期按进入时间 FIFO |
| AC-05 | 拖拽或移动合同 | 先生成未提交变更，支持撤销，不立即改变正式计划 |
| AC-06 | 提交方案 | 提交前显示合同、批次、延期、备货、等待队列和冲突变化 |
| AC-07 | 全量重算 | 已确认、生产中和锁定数据不被覆盖或丢失 |
| AC-08 | 未排合同 | 每个未排合同都有明确原因和建议动作 |
| AC-09 | 交期提前 | 系统给出建议前移位置、被影响合同和延期风险 |
| AC-10 | 交期延后 | 系统给出后移建议，未授权时不直接修改已确认或生产中队列 |
| AC-11 | 已确认批次派工 | 可直接查看可用产线、不可用原因和派工预览 |
| AC-12 | 生产中线内调度 | 提交前可见调整前后位置、被后移合同和交期影响 |
| AC-13 | 并发修改 | 方案版本过期时阻止覆盖，并提示刷新重新比较 |
| AC-14 | 服务异常 | 页面说明具体不可用模块，保留未提交草稿并允许重试 |

### 15.2 P1 验收

| 编号 | 验收场景 | 通过标准 |
|---|---|---|
| AC-15 | 方案解释 | 每个批次可查看形成原因、规则参数和风险 |
| AC-16 | 方案指标 | 显示合同数、备货数、延期数、等待队列数和比例偏差 |
| AC-17 | 批次/时间轴切换 | 两种视图数据一致，选中批次可互相定位 |
| AC-18 | 操作记录 | 可查看比例调整、重算、确认、派工和调度记录 |
| AC-19 | 新手引导 | 用户可跳过、重新打开，并能完成核心四步流程 |

## 18. 风险与依赖

| 风险/依赖 | 影响 | 应对 |
|---|---|---|
| 现有拖拽接口直接写数据库 | 难以实现真正草稿 | 首期增加前端变更集或新增批量提交接口 |
| 合同进入时间字段不稳定 | 同交期 FIFO 无法准确执行 | 明确权威字段并补齐历史数据策略 |
| 前端 5174、FastAPI 8000、Go 3001 三层依赖 | 任一服务异常会造成页面局部失败 | 增加分层健康状态和业务化错误提示 |
| 批次卡片数量大 | 页面性能和认知负担高 | 默认聚合、虚拟滚动、按大类加载 |
| 比例补齐存在取整偏差 | BOSS 认为结果不符合比例 | 显示取整规则、目标比例和实际比例 |
| 交期变化与产线实际状态不同步 | 调度建议可能不可执行 | 调度前强制刷新并校验版本/锁定状态 |

## 19. 待确认事项

以下问题会影响接口或业务规则，需要产品评审确认：

1. 同一交期的 FIFO 权威时间使用合同创建时间、审核通过时间还是进入排产池时间。建议使用“进入排产池时间”。
2. BOSS 比例配置是按全局长期生效、按大类长期生效，还是每个方案单独保存。建议“按大类保存默认值，每个方案保留快照”。
3. 比例补齐的取整规则采用最大余数法、四舍五入还是固定优先级。建议最大余数法，保证总容量不变。
4. 已确认但未派工的批次是否允许直接调整。建议必须先撤销确认，再回到预测方案调整。
5. 生产中合同前移是否必须二次审批。建议新增延期或影响多个合同达到阈值时需要 BOSS/管理员确认。
6. 跨线调度第一阶段是否开放。若产线兼容规则尚不完整，建议首期只提供建议和人工确认，不自动执行。

## 20. 发布判定

满足以下条件后，第一阶段可发布：

- AC-01 至 AC-14 全部通过。
- 已确认和生产中数据保护完成回归验证。
- 比例调整、合同交期变化、急单和线内调度至少各完成一条真实业务链路验证。
- 前端不再将依赖服务错误统一显示为角色接口或通用 500。
- 业务用户完成一次无指导验收，并能正确解释“草稿、待确认、待派工、生产中”的区别。
