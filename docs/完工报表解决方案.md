# 完工报表问题诊断与解决方案

## 🎯 需求确认

1. **"产出"定义**：生产线完工
2. **当前问题**：数量与预期不符
3. **报表用途**：产量统计和对账

---

## 🔍 生产看板的完工判断逻辑

### 前端判断逻辑（UnitCard.vue:162-172）

```javascript
const progressClass = computed(() => {
  const contractNo = String(props.unit.contract_no || '').trim()
  const status = String(props.unit.fg_status || props.unit.status || '').trim()
  const hasContract = contractNo.length > 0
  
  // 完工判断逻辑
  const isCompleted = hasContract
    ? (status === '待发货' || status === '已出库')  // 有合同号：待发货或已出库
    : (status !== '待入库')                        // 无合同号：不是待入库就算完工
  
  return isCompleted ? 'state-completed' : 'state-in-progress'
})
```

### 关键发现

**完工的判断标准**：
1. **有合同号**：`fg_status` 为 `待发货` 或 `已出库`
2. **无合同号**：`fg_status` 不是 `待入库`（即：`库存中`、`待发货`、`已出库` 都算完工）

**`fg_status` 字段**：
- 这是 `finished_goods_data` 表中的 `状态` 字段
- 通过 JOIN 关联到 `units` 表

## ⚠️ 当前完工报表的问题

### 问题1：数据来源不一致

**当前报表**：
```sql
SELECT * FROM production_history_ledger
WHERE completed_at BETWEEN :start_date AND :end_date
  AND status = 'Completed'
```

**生产看板**：
```sql
SELECT * FROM units u
LEFT JOIN finished_goods_data fg ON fg.流水号 = u.serial_no
WHERE u.status = 'In_Production'
  AND (
    (u.contract_no IS NOT NULL AND fg.状态 IN ('待发货', '已出库'))
    OR (u.contract_no IS NULL AND fg.状态 <> '待入库')
  )
```

**差异**：
- 报表基于 `production_history_ledger.status = 'Completed'`
- 看板基于 `finished_goods_data.状态`（实物状态）

### 问题2：完工时间的定义不同

**当前报表**：
- 使用 `production_history_ledger.completed_at`（沙盘系统记录的完工时间）
- 需要手动点击"手动完工"按钮才会更新

**实际情况**：
- 机台可能已经入库（`finished_goods_data.状态 = '库存中'`）
- 但沙盘系统中还没有点击"手动完工"
- 导致报表中没有这台机器

### 问题3：数据不完整

**缺失的数据**：
1. 直接导入到 `finished_goods_data` 的机台（没有经过沙盘系统）
2. 手动完工前就已经入库的机台
3. 历史数据（沙盘系统上线前）

---

## 💡 解决方案

### 方案：基于 `finished_goods_data` 的状态判断完工

**核心思路**：参照生产看板的逻辑，基于实物状态判断完工

### 新的完工报表查询逻辑

```sql
-- 明细查询
SELECT
    fg.`流水号` AS `流水号`,
    fg.`批次号` AS `批次号`,
    fg.`机型` AS `机型`,
    fg.`合同号` AS `合同号`,
    fg.`客户` AS `客户`,
    fg.`代理商` AS `经销商`,
    fg.`状态` AS `当前状态`,
    fg.`Location_Code` AS `库位`,
    DATE_FORMAT(fg.`更新时间`, '%Y-%m-%d %H:%i') AS `更新时间`,
    -- 尝试关联沙盘系统数据（如果有）
    phl.`production_line_name` AS `产线`,
    DATE_FORMAT(phl.`scheduled_at`, '%Y-%m-%d %H:%i') AS `排产时间`,
    DATE_FORMAT(phl.`completed_at`, '%Y-%m-%d %H:%i') AS `完工时间`,
    TIMESTAMPDIFF(HOUR, phl.`scheduled_at`, phl.`completed_at`) AS `生产时长(小时)`
FROM finished_goods_data fg
LEFT JOIN units u ON u.serial_no = fg.`流水号`
LEFT JOIN production_history_ledger phl ON phl.unit_id = u.unit_id
WHERE fg.`更新时间` BETWEEN :start_date AND :end_date
  AND (
    -- 有合同号：待发货或已出库算完工
    (COALESCE(fg.`合同号`, '') <> '' AND fg.`状态` IN ('待发货', '已出库'))
    OR
    -- 无合同号：不是待入库就算完工
    (COALESCE(fg.`合同号`, '') = '' AND fg.`状态` <> '待入库')
  )
ORDER BY fg.`更新时间` DESC

-- 汇总查询
SELECT
    DATE_FORMAT(fg.`更新时间`, '%Y-%m-%d') AS `日期`,
    fg.`批次号` AS `批次号`,
    fg.`机型` AS `机型`,
    COUNT(*) AS `完工数量`,
    fg.`客户` AS `客户`,
    fg.`代理商` AS `经销商`,
    fg.`合同号` AS `合同号`,
    SUM(CASE WHEN fg.`状态` = '库存中' THEN 1 ELSE 0 END) AS `库存中`,
    SUM(CASE WHEN fg.`状态` = '待发货' THEN 1 ELSE 0 END) AS `待发货`,
    SUM(CASE WHEN fg.`状态` = '已出库' THEN 1 ELSE 0 END) AS `已出库`
FROM finished_goods_data fg
WHERE fg.`更新时间` BETWEEN :start_date AND :end_date
  AND (
    (COALESCE(fg.`合同号`, '') <> '' AND fg.`状态` IN ('待发货', '已出库'))
    OR
    (COALESCE(fg.`合同号`, '') = '' AND fg.`状态` <> '待入库')
  )
GROUP BY DATE_FORMAT(fg.`更新时间`, '%Y-%m-%d'), fg.`批次号`, fg.`机型`, fg.`客户`, fg.`代理商`, fg.`合同号`
ORDER BY DATE_FORMAT(fg.`更新时间`, '%Y-%m-%d') DESC
```

## 🎯 完工判断规则（与生产看板一致）

### 规则1：有合同号的机台

```
状态 = '待发货' 或 '已出库' → 完工 ✅
状态 = '待入库' 或 '库存中' → 未完工 ❌
```

**业务含义**：
- 有合同号的机台，必须配货（待发货）或出库才算完工
- 只是入库还不算完工

### 规则2：无合同号的机台（现货）

```
状态 ≠ '待入库' → 完工 ✅
状态 = '待入库' → 未完工 ❌
```

**业务含义**：
- 无合同号的机台，只要入库（库存中）就算完工
- 不需要等配货或出库

## 📊 优势对比

| 对比项 | 当前实现 | 新方案 |
|--------|---------|--------|
| **数据来源** | production_history_ledger | finished_goods_data |
| **完工判断** | 手动点击"完工"按钮 | 基于实物状态自动判断 |
| **数据完整性** | ❌ 缺少直接导入的机台 | ✅ 包含所有机台 |
| **与看板一致** | ❌ 不一致 | ✅ 完全一致 |

| **历史数据** | ❌ 可能缺失 | ✅ 完整 |
| **生产信息** | ✅ 有产线、生产时长 | ⚠️ 部分有（通过LEFT JOIN） |

```python
def get_completion_report_data_v2(
    start_date: str,
    end_date: str,
    model_type: str = "",
    customer: str = "",
    contract_no: str = ""
) -> tuple[pd.DataFrame, pd.DataFrame]:
    """
    基于finished_goods_data状态的完工报表
    与生产看板的完工判断逻辑一致

    with get_engine().connect() as conn:

                fg.`合同号` AS `合同号`,

                phl.`production_line_name` AS `产线`,
                DATE_FORMAT(phl.`scheduled_at`, '%Y-%m-%d %H:%i') AS `排产时间`,
                DATE_FORMAT(phl.`completed_at`, '%Y-%m-%d %H:%i') AS `完工时间`,
                TIMESTAMPDIFF(HOUR, phl.`scheduled_at`, phl.`completed_at`) AS `生产时长(小时)`
            FROM finished_goods_data fg
            LEFT JOIN units u ON u.serial_no = fg.`流水号`
            LEFT JOIN production_history_ledger phl ON phl.unit_id = u.unit_id
            WHERE fg.`更新时间` BETWEEN :start_date AND :end_date
              AND (
                (COALESCE(fg.`合同号`, '') <> '' AND fg.`状态` IN ('待发货', '已出库'))

                "customer": customer,
                "contract_no": contract_no

        # 汇总查询
        summary_sql = text("""
            SELECT
                DATE_FORMAT(fg.`更新时间`, '%Y-%m-%d') AS `日期`,
                fg.`批次号` AS `批次号`,

                fg.`客户` AS `客户`,
                fg.`代理商` AS `经销商`,
                fg.`合同号` AS `合同号`,

                SUM(CASE WHEN fg.`状态` = '待发货' THEN 1 ELSE 0 END) AS `待发货`,
                SUM(CASE WHEN fg.`状态` = '已出库' THEN 1 ELSE 0 END) AS `已出库`
            FROM finished_goods_data fg
            WHERE fg.`更新时间` BETWEEN :start_date AND :end_date
              AND (
                (COALESCE(fg.`合同号`, '') <> '' AND fg.`状态` IN ('待发货', '已出库'))
                OR
                (COALESCE(fg.`合同号`, '') = '' AND fg.`状态` <> '待入库')
              )
              AND (:model_type = '' OR fg.`机型` = :model_type)
              AND (:customer = '' OR fg.`客户` = :customer)

            ORDER BY DATE_FORMAT(fg.`更新时间`, '%Y-%m-%d') DESC

                "start_date": start_date,
                "end_date": end_date,

            }
        )
    
    return summary_df, detail_df
```

## 📝 注意事项

### 1. 时间维度的变化

**原来**：`completed_at`（沙盘系统记录的完工时间）
**现在**：`更新时间`（finished_goods_data 的状态变更时间）

**影响**：
- 时间可能不完全准确（`更新时间` 会在每次状态变更时更新）
- 但数据更完整

**建议**：
- 如果需要精确的完工时间，可以使用 `inbound_history.inbound_time`（入库时间）
- 或者保留 `production_history_ledger.completed_at`（通过 LEFT JOIN）

### 2. 生产信息可能缺失

**新方案**：
- 通过 LEFT JOIN 关联 `production_history_ledger`
- 直接导入的机台没有生产线、生产时长等信息

**解决**：
- 在报表中标注"无生产记录"
- 或者分别统计"有生产记录"和"无生产记录"的机台

### 3. 数据对账

**新方案的优势**：
- 数量与生产看板完全一致
- 包含所有机台（直接导入 + 沙盘生产）
- 更适合产量统计和财务对账

## 🎯 总结

### 问题根源

当前完工报表基于 `production_history_ledger.status = 'Completed'`，但这个状态需要手动点击"完工"按钮才会更新，导致：
1. 数据不完整（缺少直接导入的机台）
2. 时间不准确（可能已经入库但还没点完工）
3. 与生产看板显示不一致

### 解决方案

改用 `finished_goods_data.状态` 判断完工，规则与生产看板一致：
- **有合同号**：待发货或已出库算完工
- **无合同号**：不是待入库就算完工

### 效果

- ✅ 数据完整（包含所有机台）
- ✅ 与生产看板一致
- ✅ 适合产量统计和对账
- ⚠️ 部分机台可能缺少生产线信息（通过 LEFT JOIN 补充）
