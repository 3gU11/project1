# 配货后机台状态与底色高亮优化

## 🎯 问题背景

用户提出了一个很好的观察：**配货后的机台信息和"已绑定"机台信息相同**，为什么状态不是"已绑定"而是"待发货"？

### 配货后机台的特征
- ✅ 有 `占用订单号`
- ✅ 有 `客户`、`代理商`
- ✅ 可能有 `合同号`（如果指定了合同）
- ✅ 不能再被其他订单配货

这些特征确实和"已绑定"机台很相似。

---

## 📊 当前状态设计

### 状态定义

| 状态 | 含义 | 业务阶段 |
|------|------|---------|
| `待入库` | 生产完成，等待入库 | 生产完成 |
| `库存中（库位）` | 已入库，存放在库位 | 已入库 |
| `待发货` | 已配货给订单，等待出库 | 已配货 |
| `已出库` | 已发货出库 | 已出库 |
| `已绑定` | 工厂计划中已绑定合同号（还未生产） | 计划阶段 |

### "已绑定"的特殊含义

"已绑定"状态主要用于**工厂计划导入**场景：

```python
# utils/parsers.py:177
"状态": "已绑定" if contract_no else "待入库"
```

**语义**：工厂计划中的机台，如果有合同号，就标记为"已绑定"（表示这台机器还在生产中，但已经预分配给某个合同）

---

## ⚠️ 如果改为"已绑定"会有什么问题？

### 问题1：语义混淆

- **"已绑定"原意**：工厂计划中，机台还未生产，但已预分配给合同
- **配货后的实际情况**：机台已生产完成，已分配给订单

两者的**业务阶段不同**：
- 已绑定 = 计划阶段（还未生产）
- 待发货 = 执行阶段（已生产，已配货）

### 问题2：过滤逻辑会失效

```javascript
// OrderAllocation.vue:286
if (status === '未入库' || status === '已出库' || status === '已绑定') return false
```

如果配货后状态改为"已绑定"，这些机台会被过滤掉，**无法在配货界面的"已配货"列表中显示**。

### 问题3：底色高亮逻辑不完整

**原来的逻辑**：
```javascript
const getAllocationRowClassName = ({ row }: { row: Row }) => {
  return String(row['合同号'] || '').trim() ? 'contract-specified-row' : ''
}
```

**问题**：
- 只有"有合同号"的机台才会有绿色底色
- 配货后如果没有指定合同号，底色不会变
- 用户期望：配货后的机台应该有视觉提示（底色高亮）

---

## ✅ 解决方案：优化底色逻辑

### 方案选择

经过分析，我们选择**保持"待发货"状态，优化底色高亮逻辑**：

**原因**：
1. ✅ 状态语义清晰（待发货 = 等待出库）
2. ✅ 不影响现有过滤逻辑
3. ✅ 最小改动，最安全
4. ✅ 满足用户需求（配货后有视觉提示）

### 实现代码

```javascript
// OrderAllocation.vue:388-396
const getAllocationRowClassName = ({ row }: { row: Row }) => {
  const hasContract = String(row['合同号'] || '').trim()
  const hasOrder = String(row['占用订单号'] || '').trim()

  // 有合同号 或 已配货给订单 → 绿色底色高亮
  if (hasContract || hasOrder) {
    return 'contract-specified-row'
  }
  return ''
}
```

### 样式定义

```css
/* 绿色底色 - 表示已绑定合同或已配货 */
:deep(.contract-specified-row td) {
  background-color: #ecfdf5 !important;  /* 浅绿色 */
}
:deep(.contract-specified-row:hover td) {
  background-color: #d1fae5 !important;  /* 悬停时深绿色 */
}
```

## 🎯 业务逻辑说明

### 绿色底色的含义

**优化后的语义**：
- 🟢 绿色底色 = 机台已被占用（有合同号 或 已配货给订单）
- ⚪ 白色底色 = 机台可用（无合同号 且 未配货）

### 配货流程中的视觉反馈

```
配货前：
┌─────────────────────────────┐
│ SN001 | 库存中 | 无订单 | ⚪ │  ← 白色，可配货
└─────────────────────────────┘

配货后：
┌─────────────────────────────┐
│ SN001 | 待发货 | SO-001 | 🟢 │  ← 绿色，已配货
└─────────────────────────────┘
```

用户可以一眼看出哪些机台已经被占用。

## 🔍 其他考虑过的方案

### 方案2：引入新状态"已配货"

**实现**：
```python
UPDATE finished_goods_data
SET 状态 = '已配货',  # 新状态
    占用订单号 = :order_id
```

**优点**：
- 状态更细粒度
- 语义更清晰

**缺点**：
- ❌ 需要修改大量代码
- ❌ 可能影响现有业务逻辑
- ❌ 需要更新所有状态相关的过滤、统计逻辑

**结论**：改动太大，风险高，不推荐

---

### 方案3：使用"已绑定"状态

**实现**：
```python
UPDATE finished_goods_data
SET 状态 = '已绑定',  # 改为已绑定
    占用订单号 = :order_id
```

**优点**：
- 状态语义统一（已绑定 = 已分配）

**缺点**：
- ❌ "已绑定"原本指工厂计划中的机台，语义会混淆
- ❌ 需要修改过滤逻辑（移除"已绑定"的过滤）
- ❌ 可能影响其他模块对"已绑定"状态的理解

**结论**：语义混淆，不推荐

## 📝 总结

### 最终方案

**保持"待发货"状态，优化底色高亮逻辑**

### 改动内容

**文件**：`frontend/src/views/OrderAllocation.vue`

**修改**：
```javascript
// 原逻辑：只有合同号才高亮
return String(row['合同号'] || '').trim() ? 'contract-specified-row' : ''

// 新逻辑：合同号或订单号都高亮
const hasContract = String(row['合同号'] || '').trim()
const hasOrder = String(row['占用订单号'] || '').trim()
if (hasContract || hasOrder) {
  return 'contract-specified-row'
}
return ''
```

### 效果

- ✅ 配货后的机台有绿色底色提示
- ✅ 状态语义保持清晰
- ✅ 不影响现有业务逻辑
- ✅ 最小改动，风险低

### 用户体验提升

用户现在可以通过底色快速识别：
- 🟢 **绿色** = 已占用（有合同或已配货）
- ⚪ **白色** = 可用（无合同且未配货）

这正是用户期望的视觉反馈！
