# 系统核心业务测试流程 (E2E)

本文档整理了目前自动化测试脚本 [overall_flow.spec.ts](file:///d:/CURSORpj/V7STD1.0/e2e/tests/overall_flow.spec.ts) 中覆盖的系统整体业务流。
当前测试涵盖了整机全生命周期的 3 条核心链路，串联了合同、排产、入库、订单、配货、发货等核心模块。

## 1. 正向主流程：现货合同直发
**适用场景**：客户签订合同后，直接使用现有库存发货，不经过生产排产。

**执行步骤**：
1. **录入现货合同**：在“合同管理”中新建合同，类型选择为现货（不进入沙盘）。
2. **成品入库**：如果当前选中的测试机台为“待入库”状态，则在“成品入库”页面将其上架至指定库位，使其状态变为“库存中（库位）”。（如果已在库存中则自动跳过）。
3. **订单生成**：在“销售下单”页面，通过导入刚才已规划的现货合同，自动生成销售订单。
4. **订单配货**：在“订单配货”页面，为该订单分配测试机台，完成配货。
5. **发货复核**：在“发货复核”页面，对该订单进行发货确认。

**核心校验点**：
- 合同状态流转：`待规划` -> `已规划`
- 订单生成后能在配货页列表看到
- 配货完成后，订单状态变更为 `ready`，机台进入 `待发货` 状态
- 发货完成后，订单状态变更为 `done`，机台状态变更为 `已出库`，并且从待办列表中消失

---

## 2. 逆向主流程：发货撤回与库存恢复
**适用场景**：销售手动建单配货后，在发货前因故撤回，验证机器能否正确回退到原库存状态。

**执行步骤**：
1. **手动创建订单**：在“销售下单”页面，不关联任何合同，直接手工创建一条新订单。
2. **订单配货**：在“订单配货”页面，将系统中一台空闲机台分配给该订单。
3. **发货撤回**：在“发货复核”页面，不点击发货，而是对该订单执行“撤回发货”操作。

**核心校验点**：
- 撤回后，机台状态正确回滚：
  - 若原机台有库位记录，恢复为 `库存中（库位）`
  - 若原机台无库位记录，恢复为 `待入库`
- 撤回后，该订单从“发货复核”页面的待办列表中移除

---

## 3. 生产排产主流程：老板计划链路
**适用场景**：客户签订合同后，库存不足或需定制，需进入“老板计划”沙盘进行生产排产，生产完工后再入库发货。

**执行步骤**：
1. **录入合同并进入沙盘**：在“合同管理”中新建合同，并勾选“进入沙盘”，合同初始状态为 `待规划`。
2. **老板计划审核确认**：在“老板计划 -> 预测沙盘”中，找到对应的预测批次卡片，点击“审核确认”。
3. **生产分配与完工**：系统后台完成产线分配与手动完工操作，批次状态变为 `Completed`，机台流转为可入库/可发货状态，合同状态同步为 `已规划`。
4. **订单生成**：在“销售下单”页面，导入已规划的合同生成订单。
5. **订单配货与发货**：对生成的订单执行配货，并在发货复核页完成发货。

**核心校验点**：
- 批次生成及状态流转：`Predicted` -> `Confirmed` -> `Completed`
- 老板计划沙盘与合同状态的联动（沙盘完工后合同变为 `已规划`）
- 走完排产链路的机器能正常被销售订单锁定并完成出库闭环

---

## 运行方式
可以在项目根目录或 `e2e` 目录下运行以下命令执行全量业务流程测试：

```bash
npx playwright test tests/overall_flow.spec.ts
```

如果只想运行单条链路，可以使用 `--grep` 参数：
```bash
# 只运行老板计划链路
npx playwright test tests/overall_flow.spec.ts --grep "老板计划"
```
